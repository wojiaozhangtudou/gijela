# REQ-20260509-001 日志看板与对话链路可观测性修复（已归档）

- 归档批次：2026-05-bugfix-close
- 归档时间：2026-05-09
- 结论：已完成并关闭（关联 Bug 已全部 closed）

## 1. 背景
- 当前问题：日志看板和对话链路存在多处可观测性缺口，影响联调与排障效率。
- 触发原因：在多轮联调中暴露出 token 统计缺失、日志清空后指标残留、日志粒度不足等问题。
- 业务价值：提升排障可见性和数据可信度，降低研发和测试沟通成本。

## 2. 目标
- 目标 1：修复流式 token 统计缺失问题，保证前端与日志都可读取到 token 信息。
- 目标 2：补齐日志看板清理、查询、追踪链路中的数据一致性。
- 目标 3：提升运行时日志粒度，支持按流式增量排查模型输出与 token 变化。

## 3. 范围
### 3.1 In Scope
- OpenAI 兼容流式解析完成时机修复。
- 日志清空接口与前端一键清理能力。
- 清日志后的缓存一致性修复。
- 日志查询结果结构补齐（`outputText`、`eventType`、`logType`）。
- 运行时逐 delta 记录（`chat.delta`）。
- SRE TopN 去重（按 `traceId`）。

### 3.2 Out of Scope
- 不改动核心权限体系。
- 不引入新的日志存储中间件。
- 不改造非日志相关业务模块。

## 4. 影响模块
- 后端：`gijela-core-chat`（日志查询、编排服务、OpenAI 兼容 SDK）。
- 前端：`gijela-bloom-chat`（日志看板、Audit/Trace 展示、清理按钮）。
- 安全/权限：沿用现有鉴权和权限控制，不新增并行体系。
- 数据/缓存：Elasticsearch 索引查询、Redis 查询缓存。

## 5. 方案约束
- 保持模块边界：Controller 不堆业务逻辑，核心行为放 Service。
- 接口风格保持 `/api/v1/**` 与统一响应链路一致。
- 前端 API 统一放 `src/api`，页面层不散写请求细节。

## 6. 数据与接口契约
### 6.1 请求
- 新增：日志一键清理接口。
- 更新：日志查询返回字段补齐运行时可观测字段。

### 6.2 响应
- 列表、追踪、审计查询结果包含 `outputText`、`eventType`、`logType` 等字段。
- 错误处理沿用统一错误码体系。

### 6.3 事件/日志
- 运行时新增 `chat.delta` 事件，记录增量文本与 token 估算。

## 7. 权限与安全
- 鉴权方式：沿用现有 JWT 链路。
- 权限点：复用已有日志查看/操作权限。
- 审计要求：清日志行为可追踪，关键操作保留审计语义。

## 8. 前端交互
- 日志看板增加“一键清空日志”操作。
- Audit/Trace 页面可查看模型输出文本和事件类型。
- 概览页在清理后不再显示过期缓存指标。

## 9. 性能与稳定性
- 实时指标优先直查，避免缓存旧值导致误判。
- TopN 慢请求按 trace 维度去重，提升可读性。
- 关键修复均以最小必要改动实施，避免大范围重构。

- [x] 日志可一键清理且概览指标不读旧缓存

- [x] 慢请求 TopN 不再被同一 trace 重复占位
- [x] 文档已同步
