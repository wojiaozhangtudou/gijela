# REQ-20260520-001：chat-flow Phase 1 会话工作台实现

## 1. 背景
- 当前问题：系统缺少将"工作流"与"对话会话"结合的用户界面，用户无法通过对话形式与 AI 工作流交互。
- 触发原因：chat-flow 模块独立域建设需求，需要实现 Phase 1 会话基础能力闭环。
- 业务价值：用户可创建绑定工作流的会话，通过对话触发工作流执行，查看执行过程与历史。

## 2. 目标
- 实现会话创建/编辑/删除，会话必须绑定已发布工作流。
- 实现对话消息发送，触发工作流异步执行，将执行结果写回对话。
- 实现执行面板实时展示当次工作流运行节点日志。
- 实现运行历史弹框，支持会话级过滤（通过 `trigger_by` 数据库字段）。

## 3. 范围

### 3.1 In Scope
- 后端：会话 CRUD API、消息分页 API、Completion API（触发工作流异步运行）
- 后端：工作流运行列表新增 `triggerBy` 过滤参数，运行记录入库时写入 `sessionId`
- 前端：三栏布局工作台（会话列表 | 消息区 | 执行面板）
- 前端：运行历史弹框，支持切换"仅当前会话/同工作流全部会话"

### 3.2 Out of Scope
- 权限与审计（延后独立立项）
- 流式输出（SSE/WebSocket）
- 多租户隔离
- 游标分页

## 4. 影响模块
- 后端：`gijela-core-chat-flow`（新增 chatflow 子域：session / message / completion）
- 前端：`gijela-bloom-chat-flow`（新增 ChatflowWorkbench 页面）
- 数据：`cf_chatflow_session`、`cf_chatflow_message`、`cf_workflow_run`（`trigger_by` 字段复用）

## 5. 方案约束
- 会话只允许绑定 `status=active` 且 `published_version > 0` 的工作流。
- 会话删除采用软删（`deleted=1`），不异步归档。
- `trigger_by` 字段已存在于 `cf_workflow_run` 表，chat completion 场景写入 `sessionId`；工作流调试场景写入 `"system"`（原行为不变）。
- Phase 1 不做重试，超时由前端兜底（降级展示 `finalResult`）。

## 6. 数据与接口契约

### 6.1 会话接口
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/chat-flow/chat/sessions` | 分页查询会话（支持关键词搜索） |
| POST | `/api/v1/chat-flow/chat/sessions` | 创建会话（绑定工作流） |
| PUT | `/api/v1/chat-flow/chat/sessions/{sessionId}` | 更新会话标题/工作流/固定入参 |
| DELETE | `/api/v1/chat-flow/chat/sessions/{sessionId}` | 软删会话 |
| GET | `/api/v1/chat-flow/chat/sessions/{sessionId}/messages` | 分页查询消息（默认 pageSize=50） |

### 6.2 Completion 接口
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/chat-flow/chat/completions` | 触发工作流异步运行，立即返回 runId |

**请求**
```json
{
  "sessionId": "sess_xxx",
  "content": "用户输入"
}
```

**响应**
```json
{
  "sessionId": "sess_xxx",
  "messageId": "msg_xxx",
  "answer": "",
  "workflowId": "wf_xxx",
  "runId": "run_dbg_xxx",
  "createdAt": "2026-05-20T10:00:00"
}
```

### 6.3 工作流 LLM 输入协议（固定注入）
CHAT 模式自动注入，不可手动修改：
- `sys.query`：用户本轮输入
- `sys.chat_history`：最近 10 条消息 JSON
- `sys.conversation_id`：当前 sessionId

### 6.4 运行列表新增参数
`GET /api/v1/chat-flow/workflows/{workflowId}/runs?triggerBy={sessionId}` 新增 `triggerBy` 过滤。

### 6.5 消息 VO 新增字段
`ChatflowMessageVO` 返回 `runId`（从 `extra_json` 中解析），前端用于关联运行详情。

## 7. 权限与安全
- 本期不做细粒度权限，延后立项。
- 严禁在接口返回中暴露系统内部错误堆栈。

## 8. 前端交互

### 8.1 三栏布局
- 左栏（320px）：会话列表，支持搜索/新建/编辑/删除。
- 中栏（自适应）：消息区，支持 Ctrl+Enter 发送，发送后 loading 等待运行完成。
- 右栏（320px）：执行面板。

### 8.2 执行面板
- 头部按钮：**运行历史**（打开弹框）、**刷新**（手动刷新当前运行）。
- 实时执行区：展示当前运行的状态/耗时/类型标签 + 节点日志（点击节点可查看输入输出 snapshot）。
- 节点日志：按状态着色（绿色=成功，红色=失败，蓝色=进行中），支持点击弹框查看详情。

### 8.3 运行历史弹框
- 左侧列表：展示工作流所有运行记录，每条标记：
  - 会话归属标签（`当前会话` / `其他会话`，由后端 `triggerBy` 字段判断）
  - 运行类型标签（`调试` / `正式`）
  - 状态标签（成功 / 失败 / 运行中）
- 右侧详情：点击运行记录，展示节点日志与最终结果。
- 切换开关：**仅当前会话** / **显示同工作流全部会话**，切换时重新请求后端（DB 级过滤）。

### 8.4 空态 / 异常态
- 未选会话：执行面板显示"请先选择会话"（图标缩小至 60px）。
- 发送超时：前端降级将 `finalResult.answer` 兜底插入消息列表，标注本地消息。
- 运行轮询失败：自动停止轮询，提示"获取执行详情失败，请稍后重试"。

## 9. 性能与稳定性
- 执行结果轮询间隔：1 秒，最多轮询至状态非 `running` 自动停止。
- 消息回填兜底：轮询结束后最多重试 3 次拉取消息，仍无 assistant 回复则从 `finalResult` 兜底展示。
- 超时无重试：Phase 1 不重试，超时前端直接降级。
- 后端异步执行：Completion 触发后立即返回 `runId`，实际执行在 `chatFlowTaskExecutor` 线程池中进行。

## 10. 验收标准
- [x] 会话创建成功，只能选择已发布工作流。
- [x] 会话发送消息后，工作流异步触发，`trigger_by` 写入 `sessionId`。
- [x] 执行面板实时展示节点执行日志，点击节点可查看输入/输出 snapshot。
- [x] 执行完成后，消息区自动回填 assistant 回复。
- [x] 运行历史弹框可按会话过滤（DB 层 `WHERE trigger_by = sessionId`）。
- [x] 前端编译通过（`pnpm build`），后端编译通过（`mvn compile`）。
- [x] CHAT 模式提示词锁定，不可手动修改入参映射。
- [x] TRANSFORM 模式支持自定义输入映射，strict 校验（无映射则拒绝执行）。
