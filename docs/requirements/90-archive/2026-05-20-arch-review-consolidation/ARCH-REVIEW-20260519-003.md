# ARCH-REVIEW-20260519-003：对 ARCH-REVIEW-20260519-002 的开工复审（chat-flow 独立域）

## 一、可落地性结论
- 结论：**有条件可落地（可启动 Phase 1 开发）**。
- 依据：
  - 已明确业务边界：`gijela-core-chat` 与 `chat-flow` 无业务关系，方向正确。
   - 已明确范围边界：本期实现不包含权限与审计能力。
  - 分阶段路线清晰（Phase 1/2/3）且与当前实现能力匹配。
  - 但“开工前置物”仍缺少部分 P0 细化，若不先补会导致实现口径分叉。

## 二、关键问题与调整建议
1. 问题：接口契约粒度不足，无法直接并行开发。
   - 位置：第 3 章（3.3 数据流设计）、第 4 章（Phase 1）。
   - 风险：前后端对 `/api/v1/chat-flow/chat/completions` 的请求/响应字段理解不一致。
   - 建议：补一页“API 合同表”（请求字段、必填、示例、错误码），至少覆盖：
     - `POST /chat/completions`
     - `GET/POST/PUT/DELETE /chat/sessions`
     - `GET /chat/sessions/{id}/messages`
   - 优先级：P0

2. 问题：数据迁移与索引策略未落地到可执行脚本。
   - 位置：3.2 Session 绑定设计。
   - 风险：上线后查询慢、回滚不可控。
   - 建议：补 DDL 细节：唯一键、联合索引、默认值、字符集、回滚 SQL；并明确 `workflow_inputs/extra_json` 的 JSON 校验策略。
   - 优先级：P0

3. 问题：范围边界需进一步固定，避免开发期混入权限/审计需求。
   - 位置：第 4 章（Phase 1）与第 9 章（P0 前置物）。
   - 风险：若临时加入权限/审计，会导致表结构与接口契约反复变更。
   - 建议：在开发任务与提测清单中明确“权限与审计不在本期范围”，相关能力延后到后续需求单独立项。
   - 优先级：P0

4. 问题：稳定性策略缺少“超时-重试-降级”统一口径。
   - 位置：第 5 章第 1 条。
   - 风险：失败路径不一致，前端体验抖动。
   - 建议：明确：
     - 执行超时阈值（如 60s）
     - 是否重试（Phase 1 建议不重试）
     - 标准降级文案与错误码映射（如 `CHATFLOW_RUN_TIMEOUT`）
   - 优先级：P0

5. 问题：测试门槛还不够“可验收”。
   - 位置：第 4 章各 Phase 验收标准。
   - 风险：提测后反复返工。
   - 建议：补最小测试清单：
     - 单测：ConversationService 输入组装、错误码映射
     - 集成：会话创建→发消息→落库→取历史
     - 回归：现有 workflow 编辑/调试/运行不受影响
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步：补齐 Phase 1 的 API 合同 + 错误码（文档先行，明确不含权限/审计）。
- 第二步：提交数据库 DDL/回滚脚本 + Mapper/Entity 骨架（后端先行）。
- 第三步：实现 `/chat/sessions` 与 `/chat/completions` 最小闭环，并完成端到端联调。

## 四、已定默认决策
1. `chat/completions` 保留 `requestId` 作为可选幂等键，服务端本期不强制校验。
2. 会话历史默认页码分页，`pageSize` 默认 50（上限 100），本期不做游标分页。
3. 会话删除采用软删，不做异步归档。
4. Phase 1 强制只允许绑定 `status=active` 且 `published_version>0` 的工作流。
