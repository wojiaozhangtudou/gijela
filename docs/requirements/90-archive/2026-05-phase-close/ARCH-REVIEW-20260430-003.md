# ARCH-REVIEW-20260430-003 Skills 体系升级方案（从代码内置注册到技能包化）

- 评审日期：2026-04-30
- 目标：基于现有 `SkillRegistry` 实现，升级到“可管理、可版本化、可分发”的 Skills 体系，并尽量对齐官方 Agent Skills 思路。

## 一、可落地性结论
- 结论：有条件可落地（建议分三阶段推进）
- 依据：
  1. 当前已具备工具调用主链路（schema 注册 + execute + auto-continue）。
  2. 当前缺口主要在“技能包元数据、加载器、版本治理、分发机制”，不在模型调用能力本身。
  3. 可通过“兼容模式”平滑迁移，避免一次性重构风险。

## 二、关键问题与调整建议
1. 问题：技能定义与执行逻辑硬编码耦合
   - 位置：`SkillRegistry.resolveToolSchemas()` / `SkillRegistry.execute()`
   - 风险：新增技能需改代码发布；不可复用、不可热更新。
   - 建议：引入 `SkillManifest + SkillRuntime` 抽象：
     - `SkillManifest`：name/description/version/inputs/outputs/capabilities
     - `SkillRuntime`：`resolveSchema()` / `invoke()`
     - `SkillRegistry` 只做路由，不承载业务逻辑
   - 优先级：P0

2. 问题：缺少技能包标准目录与元数据
   - 位置：当前仓库无 skills 包目录
   - 风险：无法形成统一交付件；跨环境不可移植。
   - 建议：落地最小包规范（兼容官方思路）：
     - `skills/<skill-name>/SKILL.md`（frontmatter: `name`、`description`、`version`、`entry`）
     - `skills/<skill-name>/references/`
     - `skills/<skill-name>/assets/`
     - `skills/<skill-name>/scripts/`（可选）
   - 优先级：P0

3. 问题：无版本治理与发布策略
   - 位置：技能无 `skill_id/version`
   - 风险：灰度、回滚、审计不可控。
   - 建议：新增 `chat_skill_registry` 表（或配置中心）记录：
     - `skill_id`、`name`、`version`、`status`、`checksum`、`source`
     - 支持 `latest` 与固定版本两种解析规则
   - 优先级：P0

4. 问题：调用观测仅到请求级，缺少技能维度指标
   - 位置：现有审计未细化到 skill 维度
   - 风险：无法诊断“未命中/空结果/超时/失败”根因。
   - 建议：新增技能指标：
     - `skill_call_total`
     - `skill_call_success_total`
     - `skill_call_empty_total`
     - `skill_call_latency_ms`
     - 维度：tenant/model/skill/version
   - 优先级：P1

5. 问题：权限模型未细粒度化
   - 位置：当前技能只按是否注册控制
   - 风险：高风险技能无法按租户/场景禁用。
   - 建议：新增技能授权策略：
     - `tenant -> allowed_skills`
     - `session -> temporary_allowed_skills`
     - `skill -> max_qps/max_timeout/max_payload`
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步（兼容层，不破坏现网）
  - 保留现有 `SkillRegistry` API；新增 `SkillProvider` 接口与默认实现。
  - 将 `knowledge.search`、`attachment.context` 从 `if-else` 拆成独立 provider。

- 第二步（包化与元数据）
  - 引入 `skills/` 目录与 `SKILL.md` 解析器。
  - 启动时扫描本地 skills 包，注册为运行时技能；未包化技能继续走 legacy provider。

- 第三步（版本与治理）
  - 增加技能版本解析、启停开关、灰度发布。
  - 增加 skill 维度观测与审计日志。

## 四、待拍板决策
1. 首期 skills 包来源：仅本地仓库目录，还是支持远程仓库拉取？
2. 版本策略：`latest` 默认可用，还是必须固定版本？
3. 是否在 P0 就支持热加载（无需重启），还是先冷加载（重启生效）？
4. `SKILL.md` frontmatter 字段最小集是否确定为：`name/description/version/entry`？
