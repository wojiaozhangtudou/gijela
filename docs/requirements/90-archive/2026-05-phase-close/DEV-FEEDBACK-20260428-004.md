# DEV-FEEDBACK-20260428-004 流式异步重构后异常边界失配

## 问题分类
- 实现风险

## 问题位置
- 需求/架构位置：`REQ-20260427-002` 第三章 P0-5（流式输出抽象）
- 涉及文件：
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClient.java`

## 影响范围
- 功能：无直接业务功能偏差。
- 稳定性：流式实现从同步执行改为后台线程后，外层 `try-catch` 仍保留 `SocketTimeoutException/IOException` 捕获，导致编译失败并阻塞测试验证。

## 严重级别
- Major

## 现象
- Maven 编译报错：对应 `try` 语句主体不再抛出 `SocketTimeoutException` / `IOException`，异常边界与实现位置不一致。

## 修正建议
- 将网络异常处理下沉到后台线程执行路径；`stream()` 外层仅负责参数校验、线程启动与关闭句柄返回。
- 后续涉及异步重构时，优先同步调整异常捕获边界与测试覆盖。

## 临时绕行方案
- 无（属编译阻断问题）。

## 处理结果
- 已移除 `stream()` 外层无效 checked-exception 捕获。
- 已在后台线程内保留 `IOException` / `LlmException` / 通用异常分类处理。
- 已补充流式 Function Calling 自动续跑测试并执行通过。
- 结论：该反馈项已闭环。
