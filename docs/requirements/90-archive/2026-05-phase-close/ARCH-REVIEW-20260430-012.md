### 二、关键问题与调整建议
1. 问题：目标与范围存在“完成实现未完成验收”偏差
   - 位置：`ARCH-REVIEW-20260430-007` / 「P0 十日排期 / Day 3、Day 4、Day 5」
   - 风险：代码可编译但业务口径（引用展示恢复）未确认，造成“看似完成、实际不可交付”。
   - 建议：将“引用恢复联调（knowledge.search + attachment.context）”明确升级为 Day2 收口阻断项，验收口径写入：必须在 done 事件可见 references。
   - 优先级：P0

2. 问题：架构边界上仍存在适配层绕过编排语义的风险
   - 位置：`ARCH-REVIEW-20260430-007` / 「P0 十日排期 / Day 3」
   - 风险：若 fallback 路径仅做本地 follow-up 而不发标准事件，会再次绕过编排层引用提取链路。
   - 建议：在适配层增加硬约束：凡触发工具执行（含文本 fallback）必须发标准 `tool_result` 事件；新增启动自检日志统计该类事件数量。
   - 优先级：P0

3. 问题：协议与数据契约缺少“fallback 场景专用”验收条目
   - 位置：`skills/ToolResult-contract-v1.0.md` / 「2. 顶层结构（固定）」与 `skills/test-matrix-v1.0.md` / 「4. 功能回归（FR）」
   - 风险：主链路通过但 fallback 场景回归，导致引用丢失反复出现。
   - 建议：新增 FR 用例（建议 FR-06）：当模型输出文本工具指令时，系统仍需产出标准 `tool_result`，并在最终响应附带 references。
   - 优先级：P0

4. 问题：性能容量约束尚未覆盖“连续 fallback 工具调用”
   - 位置：`skills/test-matrix-v1.0.md` / 「6. 性能测试（PF）」
   - 风险：极端情况下多轮 fallback 会拉高端到端延迟，影响主回复 SLA。
   - 建议：补充 PF 子场景：单轮最多工具调用次数与总耗时上限（例如最多 3 次、累计工具耗时上限 5s），超限走降级回复。
   - 优先级：P1

5. 问题：稳定性策略尚未对 fallback 失败做统一降级分层
   - 位置：`ARCH-REVIEW-20260430-007` / 「P0 十日排期 / Day 6、Day 7」
   - 风险：工具失败会出现“静默失败”或上下文不一致，影响可解释性。
   - 建议：明确降级顺序：工具失败 -> 输出可解释文案 -> 主回复继续；并记录 `error.code` 到审计字段。
   - 优先级：P1

6. 问题：安全与合规对本地技能路径缺少环境隔离约束
   - 位置：`skills/SKILL-frontmatter-v1.0.md` / 「6. 生产策略」
   - 风险：固定本地目录在生产环境可能被误启用，带来非预期技能加载风险。
   - 建议：新增环境规则：生产环境禁用本地目录扫描（或仅允许只读白名单目录+签名校验）。
   - 优先级：P0

7. 问题：可测试性与上线门槛未把“引用恢复”纳入 Go/No-Go
   - 位置：`ARCH-REVIEW-20260430-007` / 「Go / No-Go 闸门（Day 10）」
   - 风险：发布后再次出现“回答有内容但无引用”的体验回归。
   - 建议：在 G2 回归闸门追加硬指标：关键问答场景 references 展示通过率 100%。
   - 优先级：P0
