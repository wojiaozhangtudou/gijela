# DEV-FEEDBACK-20260429-004 流式工具续跑阶段 DONE 事件语义缺口

## 一、问题分类
- 架构缺口

## 二、问题位置
- 需求条目：`REQ-20260427-002` 第五章（流式事件契约）
- 涉及文件：
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClient.java`
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/SseEventParser.java`
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/test/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClientStreamFunctionCallingTest.java`

## 三、影响范围
- 功能：`tool_call -> tool_result` 后若提前发送 `done`，前端可能将一次会话误判为结束，导致“工具已执行但 assistant 无最终文本回复”。
- 稳定性：SSE 消费端在中间轮次提前关闭连接，出现“空 done”体验问题。
- 可测试性：原有测试默认“每轮 streamOnce 都发 DONE”，与业务侧“整次对话只在最终完成时 DONE”存在语义偏差。

## 四、严重级别
- Major

## 五、问题说明
- 当前契约只定义了事件类型集合（`start/delta/tool_call/tool_result/error/done`），但未明确在“自动工具续跑”场景下 `done` 的触发时机。
- 结果是 SDK 与业务消费端对 `done` 含义理解不一致：
  - SDK 轮次级 `done`
  - 前端会话级 `done`

## 六、修正建议
1. 契约补充：明确 `done` 为“会话级结束事件”，自动工具续跑中间轮次不得对外透出 `done`。
2. 实现落地：在 `OpenAiCompatibleClient` 中对“可继续续跑”的中间 `done` 事件进行抑制，仅最终轮次透出。
3. 测试收敛：更新流式函数调用测试预期，自动续跑场景只等待 1 次 `done`。

## 七、临时绕行方案
- 若上层已有“遇到 done 立即关闭 SSE”逻辑，短期可改为“仅在收到非空 assistant 终态或连接自然结束时关闭”。
