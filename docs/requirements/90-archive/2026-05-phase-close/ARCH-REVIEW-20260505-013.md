### 一、可落地性结论
- 结论：**可落地**。
- 依据：
  1. 同步执行、人工确认、幂等、补偿、错误码边界已冻结；
  2. 当前剩余工作已从“方案决策”转为“按顺序实施”；
  3. 只要按最小 MVP 顺序推进，可避免前后端并行返工。

### 二、关键问题与调整建议
1. 问题：若直接同时铺开前后端，容易在契约上返工
   - 位置：实施顺序
   - 风险：前端先做页面，后端 DTO/VO 改动会导致联调回退。
   - 建议：先后端契约，再前端页面，最后联调验收。
   - 优先级：P0

2. 问题：若先做页面功能而未落错误码与幂等，验收口径会失真
   - 位置：Controller / API / 页面交互
   - 风险：前端只能验证 happy path，真实异常场景无法收口。
   - 建议：错误码与幂等和主链路同批次落地，不后置。
   - 优先级：P0

3. 问题：若首批就做高级调试，会稀释主链路交付
   - 位置：`promptOverride` 与调试面板
   - 风险：主链路未稳先上调试能力，增加安全与联调复杂度。
   - 建议：首批只保留字段与权限占位，调试面板灰度后置。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：后端冻结契约
  - 完成 `GraphExtractTextRequest`、`GraphImportRequest`、`GraphExtractPreviewResponse`、`GraphImportResultResponse`
  - 补错误码：`GRAPH_FILE_TOO_LARGE`、`GRAPH_TEXT_TOO_LONG`、`GRAPH_IMPORT_CONSTRAINT_CONFLICT`
  - 固化 `/import` 的 `Idempotency-Key` 校验

- 第二步：后端主链路实现
  - Neo4j schema init
  - 文本/文件同步抽取预览
  - `/import` 手动确认入图
  - `importBatchId` 补偿删除骨架

- 第三步：前端最小页面实现
  - 页面只做：文本抽取、文件抽取、预览、确认入图、错误提示
  - 不做：任务轮询、自动入图、复杂调试面板、图可视化

- 第四步：联调验收
  - 验证 4 条主链路：文本成功、文件成功、超限失败、重复确认幂等
  - 验证 2 条异常链路：部分成功、批次补偿

### 四、待拍板决策
1. 当前无新增拍板项。
2. 如需进一步收缩范围，唯一建议是将 `promptOverride` 延后到第二批。
