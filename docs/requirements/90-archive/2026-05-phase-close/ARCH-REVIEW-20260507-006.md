# ARCH-REVIEW-20260507-006

## 需求基线（用于条目引用）
- 第1章 条目1.1：ES 索引模板、ILM 策略、ingest pipeline 具体配置冻结。
- 第1章 条目1.2：后端聚合查询服务文件级落地清单。
- 第2章 条目2.1：前端看板页面组件架构与路由规划。
- 第2章 条目2.2：支持开工前的所有配置与代码骨架。

## 一、可落地性结论
- 结论：可落地。
- 依据：
  - ES 配置标准化（模板 + ILM），无需按集群定制。
  - 后端服务遵循既有 Spring Boot 分层，复用 `ApiResponse` 与权限体系。
  - 前端页面可并行按路由独立开发，无强依赖。

## 二、关键问题与调整建议

1. 问题：ES 映射策略未冻结，后续字段扩展风险高。
   - 位置：第1章 条目1.1
   - 风险：`dynamic: true` 会导致字段类型漂移；`dynamic: false` 新字段丢失。
   - 建议：采用 `dynamic: 'strict'`，新增字段必须通过评审后更新模板。
   - 优先级：P0

2. 问题：脱敏字段在 ingest pipeline 执行时缺少统一脱敏器。
   - 位置：第2章 条目2.1
   - 风险：脱敏逻辑分散在多个地方，难以维护和审计。
   - 建议：
     - 在 ingest pipeline 中执行脱敏（ES 侧 filter）。
     - 建立脱敏规则配置表（regex pattern + 替换策略）。
     - 审计字段默认脱敏，允许白名单字段透传。
   - 优先级：P0

3. 问题：后端查询服务的缓存策略未定义。
   - 位置：第2章 条目2.1
   - 风险：实时聚合可能慢，但缓存会导致数据滞后。
   - 建议：
     - `timeseries/topn/distribution` 允许 5 分钟本地缓存（带版本号）。
     - `trace` 查询无缓存（实时）。
     - `records` 分页查询无缓存。
   - 优先级：P1

4. 问题：前端看板未定义 mock 策略，研发无法并行开发。
   - 位置：第2章 条目2.2
   - 风险：后端未就绪时，前端被阻塞。
   - 建议：
     - 前端先集成 mock 数据（本地 JSON）。
     - 后端提供 OpenAPI 文档，前端按契约生成 axios 客户端。
     - 联调时仅需切换 baseUrl。
   - 优先级：P1

5. 问题：告警规则未与看板聚合接口对齐。
   - 位置：第1章 条目1.2
   - 风险：告警基于一套规则，看板展示另一套聚合逻辑，数据口径不一致。
   - 建议：
     - 告警规则复用查询 API 的聚合逻辑（不重复计算）。
     - 规则结果落库（`llm_alert_event` 表），作为告警中心的数据源。
   - 优先级：P0

## 三、最小落地路径（MVP）
- 第一步：冻结 ES 配置（模板/ILM/pipeline），后端 pom 添加 ES client 依赖。
- 第二步：实现后端 4 个核心查询接口 + 前端 SRE 总览页骨架（mock）。
- 第三步：补 trace/records 接口与排障/审计页面，完成端到端打通。
