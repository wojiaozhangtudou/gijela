# ARCH-REVIEW-20260428-004 chat 模块是否可直接交付开发评审

### 一、可落地性结论
- 结论：有条件可落地，**暂不建议直接交付开发**。
- 依据：
  - 已有 3 份评审文档把方向、模块和实施清单基本补齐。
  - 但仍存在 4 类 P0 未冻结项：关键决策冲突、协议样例未完全固化、配置/部署边界未定、模块接入方式未定。
  - 现阶段可进入“开发前拍板”，不宜直接进入多人并行编码。

### 二、关键问题与调整建议
1. 问题：会话存储策略存在文档冲突。
   - 位置：
     - ARCH-REVIEW-20260428-002 第四章条目4（建议 MVP 采用 Redis）
     - ARCH-REVIEW-20260428-003 第四章条目1（建议 MVP 先内存，P1 切 Redis）
   - 风险：开发人员会按不同假设建接口与抽象，导致返工。
   - 建议：立即拍板其一：
     - 若目标是“快速联调”，MVP 统一定为 **内存实现 + `ConversationStore` 抽象**；
     - 若目标是“多实例联调”，MVP 统一定为 **Redis**。
   - 优先级：P0

2. 问题：同步/流式契约只到字段名，未到示例报文级别。
   - 位置：ARCH-REVIEW-20260428-003 第二章条目2、第三章条目3
   - 风险：前后端对 `usage`、`finishReason`、`tool_call/tool_result` 的字段结构理解不一致。
   - 建议：在文档中补充最小 JSON/SSE 样例，至少冻结：
     - `ChatCompletionRequest` 请求样例
     - `ChatCompletionResponse` 响应样例
     - SSE 每种事件的 `event/data` 样例
   - 优先级：P0

3. 问题：模块接入方式未定到仓库级。
   - 位置：ARCH-REVIEW-20260428-001 第四章条目1/2；ARCH-REVIEW-20260428-003 第三章条目1/2
   - 风险：开发开始后才发现 Maven/Vite 工程挂载方式不一致，影响脚手架创建。
   - 建议：明确：
     - `gijela-core-chat` 是否加入 [gijela-core/pom.xml](gijela-core/pom.xml) 顶层 `modules`
     - `gijela-bloom-chat` 是否作为 `gijela-bloom/` 下并行子项目
   - 优先级：P0

4. 问题：部署与鉴权边界未最终拍板。
   - 位置：ARCH-REVIEW-20260428-002 第四章条目1/4；ARCH-REVIEW-20260428-003 第四章条目2/4
   - 风险：后端端口、前端 token 复用、流式鉴权方式会直接影响接口实现。
   - 建议：开发前冻结以下默认决策：
     - `gijela-core-chat` 独立端口
     - `gijela-bloom-chat` 复用 `pistil` 登录态
     - 流式前端采用 `fetch + ReadableStream`
   - 优先级：P0

5. 问题：错误码映射策略还不够细。
   - 位置：ARCH-REVIEW-20260428-002 第二章条目6
   - 风险：开发各自定义 message/code，联调时前端无法统一处理。
   - 建议：补一个错误映射表：
     - `AUTH_ERROR -> UNAUTHORIZED`
     - `RATE_LIMITED -> RATE_LIMITED`
     - `TIMEOUT/NETWORK_ERROR -> NETWORK_IO_ERROR`
     - `MODEL_ERROR/UNKNOWN -> INTERNAL_ERROR`
   - 优先级：P1

6. 问题：MCP/Skills 范围虽已收敛，但示例职责还不够具体。
   - 位置：ARCH-REVIEW-20260428-002 第二章条目5；ARCH-REVIEW-20260428-003 第二章条目3
   - 风险：开发会把 mock 技能和真实网关写成同一套逻辑。
   - 建议：首期明确：
     - `SkillRegistry` 只管内置 skills：`time.now`、`echo`
     - `McpGateway` 只管 `knowledge.search` mock
   - 优先级：P1

7. 问题：交付标准可执行，但缺少“开始开发前检查单”。
   - 位置：ARCH-REVIEW-20260428-003 第三章条目3
   - 风险：开发启动时仍会遗漏关键拍板项。
   - 建议：补一个开发前 checklist：
     1. 会话存储已拍板
     2. 契约样例已冻结
     3. 模块挂载方式已拍板
     4. 鉴权与流式方案已拍板
     5. MCP/Skills 范围已拍板
   - 优先级：P0

### 三、最小落地路径（MVP）
- 第一步：先拍板 4 个 P0 决策
  - 会话存储
  - 顶层模块挂载方式
  - 流式鉴权/消费方案
  - 协议样例
- 第二步：输出开发基线文档
  - 冻结 DTO/SSE 样例
  - 冻结错误码映射表
  - 冻结目录结构
- 第三步：再交付开发
  - 后端先建骨架
  - 前端再接同步/流式主链路
