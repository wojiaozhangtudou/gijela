# ARCH-REVIEW-20260427-002 SDK 落地蓝图（对标 LangChain4j）

## 一、可落地性结论
- 结论：**可落地**。
- 依据：`REQ-20260427-002` 已完成关键拍板（SDK-only、SSE、Function Calling、热插拔规则、性能与成本基线），具备进入实施设计条件。

## 二、关键问题与调整建议
1. 问题：缺少可直接开工的 SDK 包结构与接口边界
   - 位置：`REQ-20260427-002` 第三章功能清单（P0）
   - 风险：多人并行开发时接口不统一，后续兼容成本高
   - 建议：按以下模块切分并冻结首版接口
   - 优先级：P0

### 2.1 建议的 SDK 模块划分（Maven，按现有仓库命名风格）
- 模块归属建议：放在 `gijela-core/` 下，采用现有 `gijela-core-*` 命名。
- 建议新增父聚合模块：`gijela-core-llm`（`packaging=pom`，仅做模块聚合与依赖管理）。
- `gijela-core-llm-sdk-core`
  - 统一模型：`ChatRequest`、`ChatResponse`、`LlmEvent`、`LlmError`
  - 核心接口：`LlmClient`、`StreamingLlmClient`、`ToolExecutor`、`Plugin`
- `gijela-core-llm-sdk-openai-compatible`
  - OpenAI 兼容实现：`OpenAiCompatibleClient`
  - 协议映射：请求/响应、SSE 事件解析
- `gijela-core-llm-sdk-plugin`
  - 插件 SPI：`PluginManager`、`PluginLifecycle`、`PluginManifest`
  - 热插拔运行策略：新请求新版本、在途请求旧版本
- `gijela-core-llm-sdk-observability`
  - 指标与日志：延迟、错误率、token、预算事件
- `gijela-core-llm-sdk-spring-boot-starter`（可选）
  - 自动装配、配置绑定、健康检查
- 包名前缀建议：`com.gijela.morpheus.llm.sdk.*`（避免与 `pistil` 业务包混用）。

建议结构（示意）：
- `gijela-core-llm` (parent)
  - `gijela-core-llm-sdk-core`
  - `gijela-core-llm-sdk-openai-compatible`
  - `gijela-core-llm-sdk-plugin`
  - `gijela-core-llm-sdk-observability`
  - `gijela-core-llm-sdk-spring-boot-starter`（可选）

2. 问题：流式与工具调用的统一契约未形成“代码级约束”
   - 位置：`REQ-20260427-002` 第五章验收标准 3/5/12
   - 风险：不同 provider 实现行为不一致
   - 建议：固定事件枚举与工具调用生命周期接口
   - 优先级：P0

### 2.2 建议的核心接口草案
- `LlmClient`
  - `ChatResponse chat(ChatRequest request)`
- `StreamingLlmClient`
  - `Closeable stream(ChatRequest request, LlmEventListener listener)`
- `LlmEvent`
  - `START | DELTA | TOOL_CALL | TOOL_RESULT | ERROR | DONE`
- `ToolExecutor`
  - `ToolResult execute(ToolCall call, ToolContext context)`
- `Plugin`
  - `id()`、`version()`、`capabilities()`、`onLoad()`、`onEnable()`、`onDisable()`、`onUnload()`

3. 问题：重试/限流/预算策略缺少默认参数建议
   - 位置：`REQ-20260427-002` 第三章 P0-3、P0-13；第四章性能
   - 风险：上线参数不可控，导致抖动
   - 建议：首版默认参数如下
   - 优先级：P0

### 2.3 首版默认参数（建议）
- 重试：最多 2 次；指数退避 `200ms -> 400ms` + 抖动
- 超时：连接 3s，读取 60s，总超时 65s
- 限流：租户级令牌桶（默认 50 QPS）
- 熔断：P1 实施（错误率阈值 50%，观察窗口 30s）
- 预算：租户月度预算阈值触发“告警 -> 限流 -> 模型降级”

### 2.5 请求发送与配套技术栈（本项目基线）
- 已确认：**请求发送统一使用 OkHttp3（5.x）**。
- 在 `gijela-core-llm-sdk-openai-compatible` 中，HTTP 调用、SSE 流读取、连接池与超时统一由 OkHttp 负责。
- 强约束：**所有 HTTP 请求（含模型调用、插件外呼、健康检查、预算告警回调）必须统一走 OkHttp，不允许引入或混用 Apache HttpClient / JDK HttpClient / 其他 HTTP 客户端。**

建议技术栈分层如下：

1) P0 必需（建议首版直接落地）
- HTTP：`com.squareup.okhttp3:okhttp`
- HTTP 日志：`com.squareup.okhttp3:logging-interceptor`（生产默认非 BODY，敏感头脱敏）
- JSON：`com.fasterxml.jackson.core:jackson-databind`（请求/响应与 tool 参数映射）
- 日志门面：`org.slf4j:slf4j-api`（与现有日志体系一致）

2) P1 建议（增强治理）
- 容错治理：`io.github.resilience4j:resilience4j-core`（或 retry/ratelimiter/circuitbreaker 子模块）
- 指标观测：`io.micrometer:micrometer-core`（统一输出成功率、P95、TTFB、token）

3) 可选（按需求启用）
- 本地缓存：`com.github.ben-manes.caffeine:caffeine`（短期响应缓存/去重）

不建议首期引入：
- Apache HttpClient、JDK HttpClient 与 OkHttp 混用（会增加维护复杂度与行为差异）。

执行检查（落地约束）：
- 代码评审必须检查：`java.net.http`、`org.apache.hc` 相关依赖与调用不得出现在 LLM SDK 模块。
- 新增 HTTP 能力时，必须复用统一 `OkHttpClient` 工厂与拦截器链。

4. 问题：插件热插拔缺少状态机说明
   - 位置：`REQ-20260427-002` 第三章 P0-10/11
   - 风险：并发场景状态错乱
   - 建议：固定插件状态机
   - 优先级：P0

### 2.4 插件状态机（建议）
- `LOADED -> ENABLED -> DISABLED -> UNLOADED`
- 回滚触发：健康检查失败、错误率超阈值、关键超时激增
- 回滚动作：切回上个稳定版本并记录审计事件

## 三、最小落地路径（MVP）
- 第一步：冻结 `gijela-core-llm-sdk-core` 契约（请求/响应/事件/错误码/接口）。
- 第二步：实现 `gijela-core-llm-sdk-openai-compatible`（同步 + SSE + Function Calling）。
- 第三步：实现 `gijela-core-llm-sdk-plugin`（SPI + 热插拔 + 回滚）。
- 第四步：接入观测与预算治理（指标、日志、告警）。
- 第五步：用 3 个示例插件验证 MCP/Skills/A2A 调用能力。

## 四、待拍板决策

2. 是否采用“重试 2 次 + 200/400ms 退避”默认值。
3. `llm-sdk-spring-boot-starter` 是否本期一并交付。

## 五、模块层级草案（仅文档，不落代码）

### 5.1 目录与模块关系（建议）
- `gijela-core/`
  - `gijela-core-llm/`（父聚合模块，`packaging=pom`）
    - `gijela-core-llm-sdk-core/`
    - `gijela-core-llm-sdk-openai-compatible/`
    - `gijela-core-llm-sdk-plugin/`
    - `gijela-core-llm-sdk-observability/`
    - `gijela-core-llm-sdk-spring-boot-starter/`（可选）

### 5.2 父子关系（建议）
- `gijela-core`（根父）
  - 子模块：`gijela-core-llm`
- `gijela-core-llm`（LLM 领域父）
  - 子模块：`*-sdk-core` / `*-openai-compatible` / `*-plugin` / `*-observability` / `*-starter`

### 5.3 依赖方向约束（建议）
- `gijela-core-llm-sdk-core`：只放抽象与模型，不依赖具体 provider。
- `gijela-core-llm-sdk-openai-compatible`：依赖 `sdk-core`。
- `gijela-core-llm-sdk-plugin`：依赖 `sdk-core`。
- `gijela-core-llm-sdk-observability`：依赖 `sdk-core`，不反向依赖 provider。
- `gijela-core-llm-sdk-spring-boot-starter`：聚合以上模块进行自动装配。

### 5.4 命名与包路径约定（建议）
- Artifact 命名：统一 `gijela-core-llm-*`。
- Java 包前缀：`com.gijela.morpheus.llm.sdk.*`。
- 禁止 `pistil` 业务包直接承载 SDK 核心抽象（保持领域边界）。

### 5.5 模块职责清单（可直接按此分工）

#### A. gijela-core-llm-sdk-core
- 职责：定义“协议无关”的核心抽象与统一模型。
- 必放内容：
  - 请求/响应模型：`ChatRequest`、`ChatResponse`、`EmbeddingRequest`、`EmbeddingResponse`
  - 流式事件模型：`LlmEvent`、`LlmEventType`、`LlmEventListener`
  - 工具调用模型：`ToolCall`、`ToolResult`、`ToolContext`
  - 错误模型：`LlmErrorCode`、`LlmException`
  - 核心接口：`LlmClient`、`StreamingLlmClient`、`EmbeddingClient`、`ToolExecutor`
- 禁止内容：HTTP 客户端实现、具体 provider 协议字段。

#### B. gijela-core-llm-sdk-openai-compatible
- 职责：实现 OpenAI 兼容协议适配。
- 必放内容：
  - 客户端实现：`OpenAiCompatibleClient`
  - 映射器：`OpenAiRequestMapper`、`OpenAiResponseMapper`
  - 流式解析：`SseEventParser`（将 provider chunk 映射为统一 `LlmEvent`）
  - 配置模型：`OpenAiCompatibleProperties`（`baseUrl/apiKey/model/timeout`）
- 依赖：只能依赖 `sdk-core`。

#### C. gijela-core-llm-sdk-plugin
- 职责：插件 SPI、热插拔与生命周期管理。
- 必放内容：
  - SPI：`Plugin`、`PluginCapability`、`PluginManifest`
  - 管理器：`PluginManager`、`PluginRegistry`
  - 生命周期：`PluginLifecycle`、`PluginStateMachine`
  - 热切换控制：`PluginSwitchController`（新请求新版本，在途旧版本）
  - 回滚控制：`PluginRollbackPolicy`
- 依赖：只能依赖 `sdk-core`。

#### D. gijela-core-llm-sdk-observability
- 职责：指标、日志、审计、预算事件。
- 必放内容：
  - 指标采集：`LlmMetricsCollector`
  - 审计记录：`LlmAuditLogger`
  - 预算事件：`BudgetEventPublisher`
  - 统一埋点拦截：`LlmObservationInterceptor`
- 依赖：依赖 `sdk-core`；不得反向依赖 provider 实现。

#### E. gijela-core-llm-sdk-spring-boot-starter（可选）
- 职责：Spring Boot 自动装配与配置绑定。
- 必放内容：
  - 自动配置：`LlmSdkAutoConfiguration`
  - 条件装配：`@ConditionalOnProperty`、`@ConditionalOnMissingBean`
  - `ConfigurationProperties` 绑定入口
- 依赖：可依赖 core/openai-compatible/plugin/observability。

### 5.6 分工与并行开发建议
- A 组：`sdk-core`（先冻结接口，其他模块并行基于接口开发）。
- B 组：`openai-compatible`（同步 + SSE + function calling 映射）。
- C 组：`plugin`（生命周期/热插拔/回滚）。
- D 组：`observability`（指标、审计、预算告警）。
- E 组：`starter`（可后置，不阻塞核心链路）。

### 5.7 文档级 DoD（Definition of Done）
- 每个模块必须提供：
  1. 模块职责说明（README）
  2. 对外接口列表
  3. 依赖边界说明
  4. 最小可运行示例
- 验收通过条件：模块间无循环依赖，`sdk-core` 不含 provider 细节。
