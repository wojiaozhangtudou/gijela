# ARCH-REVIEW-20260429-001 chat 模块收敛验收复核（严格版）

### 一、可落地性结论
- 结论：有条件可落地。
- 依据：
  - 主链路（同步/流式/会话历史/失败可见性）已形成闭环并通过关键测试与前端构建验证。
  - 但扩展链路仍存在“mock 未替换真实基础设施”的缺口，不能判定为“全量能力完成”。

### 二、关键问题与调整建议
1. 问题：附件对象存储仍为 mock，未接真实 RustFS/S3。
   - 位置：ARCH-REVIEW-20260428-008 条目 3、条目 7（扩展链路 RustFS 附件）。
   - 风险：线上仅保存 `chat_attachment` 元数据，无法保证对象可追溯、可下载、可治理。
   - 建议：将 `ObjectStorageGateway` 从 `rustfs-mock` 切为真实 SDK 调用，并补上传失败补偿（对象成功/DB失败、DB成功/对象失败）。
   - 优先级：P0

2. 问题：知识检索仍为 mock，未接 Qdrant 查询。
   - 位置：ARCH-REVIEW-20260428-008 条目 3、条目 7（扩展链路 Qdrant 检索）。
   - 风险：`knowledge.search` 当前无法体现真实召回质量，联调结果与生产行为偏差大。
   - 建议：落地 `KnowledgeSearchGateway` 到 Qdrant，保留 tenant filter 与最小超时重试策略。
   - 优先级：P0

3. 问题：DDL 已提供，但缺少启动自动初始化/迁移接入策略。
   - 位置：ARCH-REVIEW-20260428-008 条目 7（先建 MySQL 表 + Redis key 规范）。
   - 风险：环境切换时易出现“代码已发布但表未初始化”，形成上线阻断。
   - 建议：二选一固化：
     1) 接入 Flyway/Liquibase；
     2) 明确发布前 SQL 执行门禁并在部署文档固化。
   - 优先级：P0

4. 问题：附件与扩展链路测试覆盖不足。
   - 位置：可测试性与上线门槛（验收维度）。
   - 风险：主链路通过但扩展链路回归无护栏，后续改动易引入隐性故障。
   - 建议：补最小关键测试：
     - `AttachmentService` 成功/失败/补偿路径；
     - `McpGateway` 非法能力与超时路径；
     - 上传接口鉴权与参数边界。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：将对象存储与检索从 mock 替换为真实 RustFS/Qdrant 适配。
- 第二步：补齐 DDL 迁移策略（Flyway/Liquibase 或发布门禁脚本）。
- 第三步：补扩展链路最小测试并重新执行后端关键集 + 前端构建验收。

### 四、待拍板决策

3. Qdrant 检索失败时默认策略：降级为空结果还是返回可见错误？
