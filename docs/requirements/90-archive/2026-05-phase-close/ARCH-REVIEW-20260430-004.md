# ARCH-REVIEW-20260430-004 Skills 升级方案复核（遗漏检查）

- 评审日期：2026-04-30
- 评审对象：`ARCH-REVIEW-20260430-003`（Skills 体系升级方案）

### 一、可落地性结论
- 结论：有条件可落地（存在 5 项关键遗漏，补齐后可直接实施）。
- 依据：`003` 已覆盖“包化、版本、观测、权限”的主线，但在“契约、容量、稳定性、安全合规、测试门槛”上仍缺少可执行约束。

### 二、关键问题与调整建议
1. 问题：协议与数据契约未落到字段级
   - 位置：`003` 二-问题2/3（包规范与版本治理）
   - 风险：不同技能实现返回结构不一致，模型续跑与前端展示不可预测。
   - 建议：新增“统一 ToolResult 契约”章节，固定最小字段：`success`、`data`、`error`、`meta{skillId,version,latencyMs}`；并给出 `SKILL.md` frontmatter 必填/可选字段表（含类型与默认值）。
   - 优先级：P0

2. 问题：性能与容量无验收阈值
   - 位置：`003` 三（MVP）
   - 风险：技能包加载与执行引入额外延迟，可能导致 chat 首 token 变慢且不可控。
   - 建议：补充 SLO：
     - 技能路由新增开销 P95 <= 30ms
     - 单次技能执行超时默认 3s（可配置）
     - 单租户并发上限与队列阈值（如 100 并发/队列 200）
   - 优先级：P0

3. 问题：稳定性策略缺失（重试/熔断/降级/回滚）
   - 位置：`003` 二-问题3、三-第三步
   - 风险：外部依赖技能失败会拖垮主链路，出现“卡住”或全局错误放大。
   - 建议：补充运行策略：
     - 幂等错误最多重试 2 次（指数退避）
     - 技能级熔断（失败率阈值 + 半开探测）
     - 降级策略：失败后返回“无技能结果”并继续主回复
     - 回滚策略：版本切换失败自动回退上一稳定版
   - 优先级：P0

4. 问题：安全与合规边界未明确
   - 位置：`003` 二-问题5（权限模型）
   - 风险：skills/scripts 具备执行能力，若无沙箱与审计规范，存在越权与数据泄露风险。
   - 建议：补充安全基线：
     - 脚本执行白名单与沙箱限制（文件系统/网络）
     - 秘钥注入最小化（按 skill scope）
     - 审计字段最小集：`tenantId/sessionId/skillId/version/inArgsHash/outHash/operator`
     - 数据留存与脱敏策略（保留时长、脱敏级别）
   - 优先级：P0

5. 问题：可测试性与上线门槛不完整
   - 位置：`003` 三（MVP）
   - 风险：升级后缺少准入闸门，容易在回归中破坏现有 `knowledge.search`/`attachment.context`。
   - 建议：新增上线准入：
     - 契约测试（schema 与 ToolResult 字段）
     - 回归测试（现有 2 个核心技能全链路）
     - 压测基线（50 QPS/200 并发）
     - 灰度发布门槛（5%→25%→100%）与回滚触发条件
   - 优先级：P0

### 三、最小落地路径（MVP）
- 第一步：补“契约与安全”文档（字段、超时、熔断、审计、留存）并冻结为 P0 基线。
- 第二步：实现 `SkillProvider` 兼容层 + 统一 ToolResult 结构 + 超时/降级。
- 第三步：接入观测与测试闸门，完成灰度发布与回滚演练后全量。

### 四、待拍板决策
1. `SKILL.md` frontmatter 必填项最终清单（是否强制 `version` 与 `entry`）。
2. 技能执行沙箱方案：轻量进程隔离 vs 容器隔离。
3. `latest` 是否允许用于生产（建议生产仅固定版本）。
4. 降级语义：技能失败时是否对终端用户显式提示。
