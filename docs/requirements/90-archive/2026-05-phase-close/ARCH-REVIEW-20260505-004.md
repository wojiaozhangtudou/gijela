### 一、可落地性结论

  1. 方案方向正确，chat 模块具备落地基础；
  2. 需先通过 P0 Gate，避免“接口先行、规则滞后”造成返工。

### 二、关键问题与调整建议（Gate 化）
1. 问题：入图路径语义冲突
   - 位置：`extractMode` 与入图流程
   - 风险：存在“抽取后自动入图”旁路，审核链失效。
   - 建议：后端强制校验：三种 `extractMode` 均只允许预览，入图必须调用 `/import` 确认。
   - 优先级：P0

2. 问题：同步执行缺少超时与分批保护
   - 位置：`/extract/file`
   - 风险：大文件抽取超时，重试导致重复计算。
   - 建议：冻结同步超时阈值、分批上限与超限错误码。
   - 优先级：P0

3. 问题：导入幂等缺失
   - 位置：`/import`
   - 风险：重复提交导致重复关系和统计漂移。
   - 建议：引入 `idempotencyKey`（或 `previewId+graphSpace+importMode` 幂等键）。
   - 优先级：P0

4. 问题：图约束未初始化
   - 位置：Neo4j schema
   - 风险：并发下重复节点。
   - 建议：启动或初始化时执行 `IF NOT EXISTS` 约束与索引。
   - 优先级：P0

5. 问题：关系标识不稳定
   - 位置：关系删除/分页
   - 风险：使用内部 `id()` 难以稳定追踪。
   - 建议：定义业务主键 `relationshipId`。
   - 优先级：P0

### 三、最小落地路径（MVP 实施顺序）
- 第一步：冻结协议与约束（模式冲突、同步超时/分批、幂等、错误码、阈值）。
- 第二步：实现后端 P0（schema init、sync guard、idempotency、relationshipId）。
- 第三步：实现前端基础页（抽取预览 + 确认入图），不开放高风险开关。
- 第四步：联调并通过验收用例后，再灰度开放 `promptOverride`。

### 四、待拍板决策
1. 是否确认“所有模式都必须人工确认后入图”（建议：是）。
2. 文件抽取是否统一同步并冻结超时阈值（建议：是）。
3. `relationshipId` 生成策略：哈希字段组合是否冻结。
4. 首版容量阈值：文件大小、文本长度、`maxTokens` 上限。
5. `promptOverride` 是否仅限灰度账号。
