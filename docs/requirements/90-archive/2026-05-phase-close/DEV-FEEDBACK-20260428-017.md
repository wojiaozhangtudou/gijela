## 影响范围
- 功能：调用方若传入带空白的字符串布尔值（如 `" TRUE "`），当前实现不会 trim，行为与裸值不同。
- 稳定性：跨系统参数序列化/拼接时常见空白噪声，若语义不固定可能导致联调不一致。

## 严重级别
- Minor

## 现象
- 当前实现使用 `Boolean.parseBoolean(String)` 且未预处理空白。
- `"TRUE"` 解析为 `true`，但 `" TRUE "` 解析为 `false`。
- 之前缺少针对空白包裹值的显式断言。

## 修正建议
- 增加单测锁定当前行为：空白包裹 `true` 按 `false` 处理。
- 若后续要改为 `trim` 后解析，应先在需求文档中明确并评估兼容性。

## 临时绕行方案
- 调用方避免传递带前后空白的字符串布尔值，优先传布尔类型。
