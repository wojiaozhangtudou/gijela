# DEV-FEEDBACK-20260428-006 同步 chat 非法响应体错误码归类偏差

## 问题分类
- 实现风险

## 问题位置
- 需求/架构位置：`REQ-20260427-002` 第三章 P0-4（统一错误码与异常分层）
- 涉及文件：
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClient.java`
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/test/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClientChatErrorTest.java`

## 影响范围
- 功能：无直接业务功能缺失。
- 稳定性：当上游返回 HTTP 200 但响应体 JSON 非法时，SDK 误报为 `NETWORK_ERROR`，会误导定位与告警分流。

## 严重级别
- Major

## 现象
- 单测复现：`shouldReportModelErrorOnMalformedChatBody()` 期望 `MODEL_ERROR`，实际返回 `NETWORK_ERROR`。
- 根因：`chat()` 外层统一捕获 `IOException`，将响应体解析失败也归入网络异常。

## 修正建议
- 在成功响应分支内单独捕获 JSON 解析异常，并映射为 `LlmErrorCode.MODEL_ERROR`。
- 继续通过回放测试覆盖 429/5xx/非法响应体三类同步异常路径。

## 临时绕行方案
- 无（错误码语义会直接影响治理逻辑）。

## 处理结果
- 已在 `executeChatCompletion()` 中将成功响应体解析失败改为抛出 `MODEL_ERROR`。
- 已新增 `OpenAiCompatibleClientChatErrorTest` 覆盖 429/5xx/非法响应体场景。
- 已完成模块测试验证：`Tests run: 13, Failures: 0, Errors: 0`。
- 结论：该反馈项已闭环。
