# DEV-FEEDBACK-20260428-002 流式 tool_calls 分片聚合键缺口

## 问题分类
- 实现风险

## 问题位置
- 需求/架构位置：`REQ-20260427-002` 第三章 P0-5 / P0-7（流式事件与 Function Calling）
- 涉及文件：
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/SseEventParser.java`

## 影响范围
- 功能：OpenAI 兼容流式 `tool_calls` 在“首片带 id、后续分片仅 index”场景无法正确拼装参数。
- 稳定性：可能触发 `_raw` 兜底，影响工具参数可用性与后续执行正确率。

## 严重级别
- Major

## 现象
- 单元测试复现：参数分片后 `city` 字段解析为空。
- 根因：分片键优先用 `id`，后续无 `id` 分片回落到 `index`，导致落入不同累加器。

## 修正建议
- 在解析器增加 `index -> key` 映射并在 `id` 出现后做键迁移，确保同一次 tool_call 分片归并到同一累加器。
- 在 `finish_reason=tool_calls` 时执行兜底 flush，并保持去重。

## 临时绕行方案
- 无（该问题直接影响 Function Calling 参数正确性）。

## 处理结果
- 已在 `SseEventParser` 增加 `toolCallKeyByIndex` 及键迁移逻辑，修复分片归并。
- 已新增单元测试 `SseEventParserTest` 覆盖：
  - `START/DELTA/DONE`
  - 分片 `tool_calls` 参数拼装
  - 非法 chunk 错误事件
- 已执行模块测试验证：`gijela-core-llm-sdk-openai-compatible` `BUILD SUCCESS`。
- 结论：该反馈项已闭环，可继续推进 Function Calling 回传链路开发。
