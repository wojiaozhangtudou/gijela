# ARCH-REVIEW-20260428-009 会话摘要刷新链路一致性评审

### 一、可落地性结论
- 结论：有条件可落地。
- 依据：
  - 已修复主链路（`RedisConversationStore`）中“配置存在但未生效”的问题，`summaryRefreshRounds` 与 `summaryRefreshTokenThreshold` 已接入。
  - 但在降级路径（`InMemoryConversationStore`）中，摘要刷新策略仍未对齐，属于非阻塞但真实一致性缺口。

### 二、关键问题与调整建议
1. 问题：轮次语义曾按“消息条数”触发，和基线“轮次”定义不一致。
   - 位置：`ARCH-REVIEW-20260428-007` 条目“上下文摘要每 10 轮或 token 超过 6000 刷新”。
   - 风险：摘要刷新频率偏高，造成写放大与摘要质量波动。
   - 建议：按 `2 条消息 = 1 轮` 计算触发；仅在跨越轮次阈值时刷新。
   - 优先级：P0

2. 问题：配置生效范围只覆盖 Redis 主链路，降级链路未统一。
   - 位置：`ARCH-REVIEW-20260428-008` 条目“默认值冻结为统一执行版本”。
   - 风险：Redis 不可用时行为漂移，环境间结果不一致。
   - 建议：为 `InMemoryConversationStore` 增加同构摘要刷新逻辑，或在文档显式声明“仅 Redis 生效”。
   - 优先级：P1

3. 问题：token 阈值采用近似估算，尚未形成统一口径。
   - 位置：`ARCH-REVIEW-20260428-007` 条目“token 超过 6000 刷新”。
   - 风险：不同模型下阈值触发时间偏差较大。
   - 建议：在配置文档中声明“当前为近似 token 估算”，后续接入真实 tokenizer 作为增强。
   - 优先级：P2

### 三、最小落地路径（MVP）
- 第一步：固化主链路（已完成）——Redis 路径按“轮次/阈值”刷新摘要并回写 `chat_conversation.summary`。
- 第二步：补齐降级链路——`InMemoryConversationStore` 对齐同构触发逻辑（或文档显式声明差异）。
- 第三步：统一口径——补充 token 估算说明，并预留真实 tokenizer 接入点。

### 四、待拍板决策
1. 降级链路是否要求“与 Redis 行为完全同构”？
2. token 阈值是否在 P0 阶段即要求真实 tokenizer，而非近似估算？
