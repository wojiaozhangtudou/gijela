# DEV-FEEDBACK-20260430-008

## 问题分类
- 架构缺口

## 问题位置
- Chat 附件上传链路默认配置与本地对象存储能力契约
- 涉及文件：
  - gijela-core/gijela-core-chat/src/main/resources/application.yml
  - gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/adapter/storage/ObjectStorageGateway.java
  - gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/service/impl/DefaultAttachmentService.java

## 影响范围
- 功能：附件上传接口 `/api/v1/chat/attachments` 在对象存储接口不匹配时直接抛 500。
- 稳定性：前端仅看到“Internal Server Error”，无法快速判断是存储配置问题。

## 严重级别
- Major

## 修正建议
1. 明确对象存储接入契约：当前实现依赖 HTTP 上传网关（`upload-path`），并非 S3 原生上传接口。
2. 在部署文档中显式区分两种模式：
   - HTTP 网关上传（当前实现）
   - S3 SDK/签名上传（后续演进）
3. 接口错误返回业务可读信息，避免统一落为“系统错误”。

## 临时绕行方案
- 若本地仅有 S3 端口服务且无 HTTP 上传网关，请临时禁用聊天附件上传入口，或将 `CHAT_STORAGE_ENDPOINT/CHAT_STORAGE_UPLOAD_PATH` 指向可用网关。

## 本次落地结果
- 后端将对象存储运行时异常转换为业务错误（`NETWORK_IO_ERROR`），并给出可执行排查提示。
- 前端附件上传失败时优先展示后端 `msg`，不再只显示泛化 500 文案。
