# DEV-FEEDBACK-20260430-009

## 问题分类
- 架构缺口

## 问题位置
- chat 附件上传实现与 RustFS(S3 端口)接口协议不一致
- 涉及文件：
  - gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/adapter/storage/ObjectStorageGateway.java
  - gijela-core/gijela-core-chat/src/main/resources/application.yml

## 影响范围
- 功能：附件上传能力在“仅提供 S3 原生端口(9000)”环境不可用。
- 稳定性：上传请求持续失败，业务端只能降级或禁用该入口。

## 严重级别
- Blocker

## 修正建议
1. 明确两种接入模式并二选一：
   - A. HTTP 上传网关模式（当前代码模式）
   - B. S3 原生模式（需新增 SigV4 签名上传实现）
2. 若选择 B，需在 chat 模块补齐 S3 直传实现与配置项（region、path-style、签名算法）。

## 临时绕行方案
- 立即将 `CHAT_STORAGE_ENDPOINT/CHAT_STORAGE_UPLOAD_PATH` 指向可用的上传网关；
- 若当前环境仅有 S3 原生端口，先在前端隐藏附件上传入口，避免用户误触失败。

## 本次落地结果
- 已确认本地 9000 端口返回 S3 风格 XML 错误（AccessDenied/MalformedPOSTRequest），不符合当前上传网关协议。
- 已将上传异常改为可读业务错误，便于快速排查。
