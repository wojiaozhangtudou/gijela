## 四、关键技术决策回顾

1. **依赖单向化**：sdk-mcp 通过 `McpToolBindingSource` SPI 反向注入业务侧数据源，避免 sdk → chat 反向依赖。
2. **自动装配**：每个 SDK 提供 `*AutoConfiguration` + `META-INF/spring/...AutoConfiguration.imports`，业务侧零配置即可获得 Bean。
3. **配置前缀**：`gijela.llm.skill.*` / `gijela.llm.mcp.*`，与业务专属字段（如 `cipherKey`）分离。
4. **不考虑历史兼容**：包路径整体迁移到 `com.gijela.morpheus.llm.sdk.{skill,mcp}.*`，旧 `chat.adapter.mcp.*` 已物理删除。

## 五、过程重要修复

| 现象 | 根因 | 处理 |
|---|---|---|
| `Get-Content -Raw` + `Set-Content -Encoding UTF8` 中文注释 mojibake | PowerShell 5.1 默认 GBK 解码 + UTF8-with-BOM 写回 | 使用 `[System.IO.File]::ReadAllText(path, UTF8)` + `WriteAllText(... UTF8Encoding($false))`；对已损坏文件用 CFR 反编译 chat target/classes 还原源码（含字符串常量 UTF-8 原文） |
| `非法字符 \ufeff` 编译错误 | `Set-Content -Encoding UTF8` 写入 BOM | 全部用 UTF-8 无 BOM 写回，并在维护脚本中固化此约定 |
| CFR 反编译变量复用 + 漏掉 IOException 声明 | CFR 0.152 在某些控制流下会复用变量名 | 手动修复 `StdioTransport`（`bufferedWriter` → `JsonNode result`）与 `StreamableHttpTransport`（`execute()` 显式包 IOException） |
