# ARCH-REVIEW-20260505-003：对 ARCH-REVIEW-20260505-002 的二次评审（问题清单）

- 日期：2026-05-05
- 状态：已评审
- 评审对象：[ARCH-REVIEW-20260505-002.md](./ARCH-REVIEW-20260505-002.md)

### 一、可落地性结论
- 结论：**有条件可落地**。
- 依据：
  1. 方案方向正确（落在 chat 模块、单库逻辑隔离、前后端链路完整）；
  2. 但当前计划在“状态机一致性、接口幂等、性能容量、安全边界、可测试性”五个维度仍有缺口，直接开工会产生返工。

### 二、关键问题与调整建议
1. 问题：入图确认规则在模式维度语义不一致
   - 位置：**十四、模式切换设计 14.1 + 14.2**
   - 风险：若不同模式有不同入图路径，前后端会出现“有时直入、有时确认”的行为分裂，造成审核链失效。
   - 建议：
     - 增加强约束：三种 `extractMode` 统一“抽取仅预览、入图必须调用 `/import` 确认”；
     - 在接口层返回明确错误码（如 `GRAPH_MODE_CONFLICT`）。
   - 优先级：**P0**

2. 问题：同步链路缺少超时与分批保护
   - 位置：**九、接口清单 9.2/9.3；十五、请求/响应契约**
   - 风险：文件抽取耗时较长，若无同步超时与分批策略，接口容易超时并触发重复提交。
   - 建议：
     - 冻结同步超时阈值与单次处理上限；
     - 大文件走“先提取文本再抽取”的同步降级路径，避免长事务。
   - 优先级：**P0**

3. 问题：缺少幂等设计，重复提交会写脏图
   - 位置：**九、接口清单 9.3-6 /import**
   - 风险：前端重试、网络抖动会重复入图，造成重复关系与统计漂移。
   - 建议：
     - `import` 增加 `idempotencyKey`（或基于 `previewId + graphSpace + importMode` 幂等）；
     - 后端保存“最后一次导入结果”，重复请求直接返回已完成结果。
   - 优先级：**P0**

4. 问题：图约束未纳入初始化步骤
   - 位置：**四、推荐落地设计 4.3；五、最小落地路径**
   - 风险：没有唯一约束会导致并发导入出现同名节点重复。
   - 建议：
     - 在 Day1 增加 schema 初始化（`IF NOT EXISTS`）：
       - 节点唯一键：`(tenantId, graphSpace, normalizedName)`；
       - 必要索引：`tenantId, graphSpace, updatedAt`。
   - 优先级：**P0**

5. 问题：关系主键不明确，删除接口不可稳定定位
   - 位置：**十、DTO/VO 10.1-7 / 10.2（关系 VO）**
   - 风险：Neo4j 内部 `id()` 不适合作为业务长期标识，删除/分页会不稳定。
   - 建议：
     - 关系增加业务键 `relationshipId`（如 hash(source,target,description,graphSpace,tenantId)）；
     - 删除与分页统一基于 `relationshipId`。
   - 优先级：**P0**

6. 问题：`promptOverride` 安全边界不完整
   - 位置：**十七、提示词前端可调试的安全边界**
   - 风险：仅做长度限制不足，存在越权调试、提示词注入导致高成本调用风险。
   - 建议：
     - 增加权限点：`graph:debug-prompt`；
     - 增加速率限制与 token 上限；
     - 审计日志补字段：`promptHash`、`model`、`tokenUsage`、`durationMs`。
   - 优先级：**P1**

7. 问题：性能与容量阈值未冻结
   - 位置：**十五、请求/响应契约；十六、前端调试面板**
   - 风险：大文本/大文件可能导致接口超时与 OOM。
   - 建议：
     - 冻结首版阈值：
       - 文件大小 <= 10MB；
       - 文本长度 <= 50k 字符；
       - 单次预览实体 <= 300、关系 <= 800；
       - `maxTokens` 上限（如 4k/8k）。
   - 优先级：**P1**

8. 问题：错误码与前端提示映射缺失
   - 位置：**九、接口清单；十五、响应契约**
   - 风险：前端只能显示“失败”，无法区分“解析失败/模型失败/图写入失败”。
   - 建议：
     - 补统一错误码：
       - `GRAPH_EXTRACT_PARSE_ERROR`
       - `GRAPH_IMPORT_CONSTRAINT_CONFLICT`
       - `GRAPH_MODE_CONFLICT`
       - `GRAPH_SPACE_NOT_FOUND`
       - `GRAPH_LLM_TIMEOUT`
     - 在 `ApiResponse.msg` 中给出可直接展示文案。
   - 优先级：**P1**

9. 问题：测试计划不足以覆盖回归风险
   - 位置：**十二、开工任务清单**
   - 风险：仅按天排任务，没有验收标准，难控质量。
   - 建议：
     - 增加最小测试矩阵：
       - parser 单测（格式噪声、空结果、非法强度）；
       - repository 单测（幂等导入、删除空间、分页查询）；
       - controller 集成测试（三模式切换 + 权限）；
       - 前端页面流转测试（文本/文件/确认入图）。
   - 优先级：**P1**

### 三、最小落地路径（MVP）
- 第一步：冻结协议（模式冲突规则、同步超时/分批策略、错误码、容量阈值）。
- 第二步：后端先做 `graph schema init + sync extract guard + import idempotency`。
- 第三步：前端上线 `GraphPage` 基础版（文本/文件抽取 + 预览 + 确认入图）。
- 第四步：补审计、权限与测试矩阵；通过后灰度开放 `promptOverride`。

### 四、待拍板决策
1. 是否确认“所有模式都必须人工确认后入图”（建议：是）。
2. 文件抽取是否统一同步执行并冻结超时阈值（建议：是）。
3. 关系业务主键策略（建议：`relationshipId` 业务键，不用 Neo4j 内部 id）。
4. 首版 token 与文件大小上限具体数值。
5. 是否在首版就开放 `promptOverride` 给前端（建议：仅灰度账号 + 权限控制）。
