- 来源：`ARCH-REVIEW-20260430-005`、`ARCH-REVIEW-20260430-006`
- 目标：给出可直接执行的 P0 十个工作日排期（按天、交付物、验收点）。

### 一、可落地性结论
- 结论：可落地（具备明确日程、交付物、验收口径）。
- 依据：
  1. 任务依赖已收敛为“契约先行、实现并行、测试闸门、灰度上线”。
  2. 关键风险（契约漂移、稳定性、发布门槛）均配置了验收点与回滚条件。

### 二、关键问题与调整建议
1. 问题：契约冻结不及时会导致后续返工
   - 位置：Day 1~2
   - 风险：BE/FE/QA并行时接口抖动
   - 建议：Day 2 下班前冻结 `ToolResult` 与 `SKILL.md` 字段，不再变更（仅允许新增可选字段）
   - 优先级：P0

2. 问题：稳定性策略若延后会阻断灰度
   - 位置：Day 6~8
   - 风险：上线前无法完成故障注入与回滚演练
   - 建议：Day 6 完成超时+降级，Day 7 完成熔断，Day 8 完成回滚演练
   - 优先级：P0

3. 问题：缺少明确 go/no-go 判定
   - 位置：Day 9~10
   - 风险：发布决策主观
   - 建议：设置量化闸门（错误率、P95、回归通过率、压测达标）
   - 优先级：P0

### 三、最小落地路径（MVP）
- 第一步：契约冻结与设计评审（Day 1~2）
- 第二步：后端核心能力开发（Day 3~6）
- 第三步：前端适配与测试闸门（Day 5~8）
- 第四步：灰度、回滚演练与发布评审（Day 9~10）

#### P0 十日排期（按天）
- Day 1（架构/后端/前端/测试联合）
  - 任务：评审并确认 `ToolResult` 契约草案、`SKILL.md` 字段草案
  - 交付物：契约草案 v0.9、字段字典
  - 验收：评审通过，遗留问题 <= 5 条且有责任人

- Day 2（后端主导）
  - 任务：冻结契约 v1.0，定义错误码与向后兼容策略
  - 交付物：契约 v1.0（冻结）、兼容说明
  - 验收：BE/FE/QA签字确认；新增字段仅可选

- Day 3（后端）
  - 任务：实现 `SkillProvider` 兼容层（legacy 与 provider 并存）
  - 交付物：路由改造 PR
  - 验收：现有 `knowledge.search`/`attachment.context` 回归通过

- Day 4（后端）
  - 任务：实现本地 `skills/` 扫描 + `SKILL.md` 解析器
  - 交付物：skills loader PR + 示例 skill 2 个
  - 验收：启动日志可见加载结果，解析失败有明确错误

- Day 5（后端+前端）
  - 任务：实现 `skill_id/version/status/checksum`；前端适配新结果结构
  - 交付物：版本治理 PR、前端展示 PR
  - 验收：可指定固定版本调用；前端展示无断言错误

- Day 6（后端）
  - 任务：实现超时、重试、降级（失败不中断主回复）
  - 交付物：稳定性策略 PR
  - 验收：超时注入场景下主回复持续可用

- Day 7（后端+安全）
  - 任务：实现熔断与沙箱/白名单基础策略
  - 交付物：熔断与安全基线 PR
  - 验收：故障连续触发后熔断生效；越权脚本被拦截

- Day 8（测试+运维）
  - 任务：契约测试、回归测试、故障注入测试、回滚演练
  - 交付物：测试报告 v1、回滚演练记录
  - 验收：核心用例通过率 100%，演练可在 10 分钟内回滚

- Day 9（测试+运维）
  - 任务：压测与灰度 5%→25%
  - 交付物：压测报告、灰度观测报告
  - 验收：50 QPS/200 并发达标；错误率 <= 1%，P95 达标

- Day 10（全体）
  - 任务：发布评审与全量决策
  - 交付物：Go/No-Go 结论、上线记录、复盘条目
  - 验收：满足全量门槛，否则触发回滚并保留灰度

#### Go / No-Go 闸门（Day 10）
- Go 条件（全部满足）
  1. 契约测试与回归测试通过率 = 100%
  2. 压测达标：50 QPS / 200 并发
  3. 线上灰度错误率 <= 1%，P95 未超阈
  4. 回滚演练成功且时长 <= 10 分钟
- No-Go 条件（任一触发）
  1. 错误率 > 1% 持续 5 分钟
  2. P95 超阈持续 5 分钟
  3. 核心技能任一链路回归失败
