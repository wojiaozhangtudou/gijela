# ARCH-REVIEW-20260430-013：技能管理后台落地方案（业界标准版）

- 评审日期：2026-04-30
- 范围：管理后台中新增"技能管理"页面（增删改查 + 详情 + 启停 + 重载），对接 `gijela-core-chat` 的 `SkillRegistry`。
- 关联：基于 ARCH-REVIEW-20260430-003 ~ 012 已落地的"技能包化（清单 + 热扫描）"体系继续演进。

## 一、可落地性结论

- 结论：**可落地，按业界标准（Dify / Coze / OpenWebUI / LangChain Hub / MCP Server Gating / Helm / OCI）分阶段落地**。
- 依据：当前 `SkillRegistry` 已支持文件清单 + 热扫描 + 全量加载，扩展为"管理面 + 运行面分离 + 元数据增强 + 启停白名单 + 审计"是自然延伸；唯一高风险点是 CRUD = 远程任意命令执行，必须通过白名单 + 鉴权 + 审计闭环兜住。

## 二、最终决策（用户已确认）

| 决策项 | 决议 |
|---|---|
| A1 范围 | **本期只做阶段 A**（只读 + 启停 + 重载）；阶段 B 的 CRUD 留下迭代 |
| A2 前端落点 | **聊天前端 [gijela-bloom-chat](../../gijela-bloom/gijela-bloom-chat)**，与 `views/KnowledgePage.vue` 同级新增 `views/SkillListPage.vue` + `SkillDetailPage.vue`（变更记录见末尾） |
| A3 数据库 | 新增 **`chat_skill_state`** 一张表，仅存"启停 + 上次加载时间 + 错误信息"；审计复用现有 `chat_audit_log` |
| A4 跨服务 | **chat 前端直连 chat 后端 9016**，复用现有 `src/api/client.ts`（baseURL `/api`，vite 已代理到 9016） |

> 变更记录（2026-04-30）：A2 由原"管理后台 pistil"调整为"聊天前端 chat"。理由：技能本身属于 chat 模块功能，chat 前端已直接对接 9016，避免跨服务代理与权限链路重复落地。

## 三、阶段 A 详细落地（本期实现）

### 3.1 后端（gijela-core-chat）

#### 3.1.1 SkillProvider 接口扩展
- 新增默认方法：
  - `default String description() { return ""; }`
  - `default String version() { return "1.0.0"; }`
  - `default SkillSource source() { return SkillSource.BUILTIN; }`（枚举：`BUILTIN / LOCAL`）
- 4 个内置 provider 显式覆盖 `description / version`，`source()` 保持默认 `BUILTIN`
- `ScriptSkillProvider` 覆盖 `source()` 返回 `LOCAL`，并从 `SkillManifest` 透出 `description / version`

#### 3.1.2 数据模型
新表 `chat_skill_state`（DDL 落 `gijela-core-chat/src/main/resources/db/migration/`，与现有 chat 表同库 `gijela_chat`）：

```sql
CREATE TABLE chat_skill_state (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  tenant_id VARCHAR(64) NOT NULL DEFAULT 'default',
  name VARCHAR(128) NOT NULL,
  enabled TINYINT(1) NOT NULL DEFAULT 1,
  source VARCHAR(16) NOT NULL,           -- BUILTIN / LOCAL
  last_loaded_at DATETIME NULL,
  error_msg VARCHAR(1024) NULL,
  updated_by VARCHAR(64) NULL,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_tenant_name (tenant_id, name)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT '技能运行态';
```

> 启停默认 `enabled=1`；`SkillRegistry.reload()` 完成后 upsert 一条 `last_loaded_at`，失败时写 `error_msg`。

#### 3.1.3 接口契约（管理面，前缀 `/api/v1/chat/admin/skills`）

| Method | Path | 说明 | 权限码 |
|---|---|---|---|
| GET | `/api/v1/chat/admin/skills` | 列表（含 enabled / source / version / lastLoadedAt / errorMsg） | `chat:skill:view` |
| GET | `/api/v1/chat/admin/skills/{name}` | 详情（含 description / entry / inputSchema / manifestRaw） | `chat:skill:view` |
| POST | `/api/v1/chat/admin/skills/{name}/toggle` | 启停（body: `{enabled: bool}`） | `chat:skill:toggle` |
| POST | `/api/v1/chat/admin/skills/reload` | 手动触发热重载 | `chat:skill:reload` |

DTO：
- `SkillSummaryVO { name, source, version, enabled, lastLoadedAt, errorMsg }`
- `SkillDetailVO extends SkillSummaryVO { description, entry, inputSchema(Map), manifestRaw(String) }`

#### 3.1.4 运行面对接
- `SkillRegistry.resolveToolSchemas(...)` 在返回前过滤 `chat_skill_state.enabled=false` 的技能名（通过 `SkillStateService` 注入）
- `SkillHotReloadScheduler` 与手动 reload 共用 `SkillRegistry.reload()`，每次 reload 完成后批量 upsert `chat_skill_state.last_loaded_at`

#### 3.1.5 安全与审计
- `SkillAdminController` 走 pistil 已建的 Spring Security 链路（沿用 `gijela-core-security-common`），通过权限码注解 `@PreAuthorize("hasAuthority('chat:skill:view')")` 等
- 所有写操作（toggle、reload）调用 `ChatAuditService.record(tenantId, requestId, null, "skill.toggle"/"skill.reload", payload)`，沿用现有 `chat_audit_log` 表

### 3.2 前端（gijela-bloom-chat）

#### 3.2.1 路由与菜单
- 新菜单项："聊天管理 → 技能管理"，路由 `/chat/skills`
- 菜单/权限通过 pistil 现有菜单管理（`views/system/MenuList.vue` 维护）配置：
  - 菜单：`chat:skill`
  - 按钮：`chat:skill:view / toggle / reload`

#### 3.2.2 API 客户端
- 新增 `src/api/chat-skill.ts`，使用独立 axios 实例 `chatClient`（`baseURL = http://localhost:9016`，开发期），生产期由网关转发，`baseURL` 走环境变量
- 与现有 `src/api/client.ts` 并列，复用 token 注入与错误处理拦截器

#### 3.2.3 页面
- `views/chat/SkillList.vue`：
  - 表格列：name / source（标签 BUILTIN/LOCAL 双色）/ version / enabled（开关）/ lastLoadedAt / errorMsg（红色文字截断）
  - 顶部按钮：手动重载（带 loading）
  - 行操作：详情（跳详情页或抽屉）
- `views/chat/SkillDetail.vue`：
  - 基本信息卡（name / description / version / source / entry / lastLoadedAt / errorMsg）
  - inputSchema（JSON 高亮只读）
  - manifestRaw（markdown 只读）

### 3.3 配置
- `application.yml` 新增（默认空，阶段 B 启用）：
  ```yaml
  gijela:
    chat:
      skills:
        scan-enabled: true
        local-path: skills
        script-allowlist: []   # 阶段 B 才启用，空 = 禁止前端创建脚本技能
  ```

### 3.4 测试矩阵（阶段 A）
- 后端单元：`SkillStateService` 启停过滤（启用 / 禁用 / 不存在的状态记录走默认 enabled=true）
- 后端单元：`SkillAdminController` 列表/详情/启停/重载 4 个接口（MockMvc）
- 后端集成：toggle 后立即查 `resolveToolSchemas` 不再包含被禁技能
- 前端：`SkillList.vue` 启停开关与重载按钮交互（element-plus message 反馈）

## 四、阶段 B 预留（下迭代实现）

> 不在本期范围，仅记录约束，避免阶段 A 设计走偏。

- 接口：`POST/PUT/DELETE /api/v1/chat/admin/skills/{name}`
- 入口允许列表：`script:` 命令必须命中 `gijela.chat.skills.script-allowlist`，`java:` 全部禁止前端创建
- 文件原子写：`skills/.staging/<name>-<ts>/` → `Files.move(ATOMIC_MOVE)`
- 软删除：`skills/.trash/<name>-<ts>/` 保留 7 天
- Schema 校验：`networknt/json-schema-validator`（Draft 7）
- 写完后**立即** `SkillRegistry.reload()`，避免与 30s 调度产生半成品
- 权限码：`chat:skill:create / update / delete`

## 五、最小落地路径（MVP 实施顺序）

1. **第一步（后端基础）**：扩展 `SkillProvider` 接口 + 4 个内置 provider 显式 description/version；新增 `SkillSource` 枚举
2. **第二步（数据层）**：建表 `chat_skill_state` + Mapper + `SkillStateService`
3. **第三步（接口层）**：`SkillAdminController` 4 个接口 + DTO + 审计接入
4. **第四步（运行面对接）**：`SkillRegistry.resolveToolSchemas` 过滤禁用项；reload 完成后 upsert state
5. **第五步（前端）**：gijela-bloom-chat 新增 2 个路由页面，复用现有 axios 实例（无需新增代理）
6. **第六步（联调验证）**：端到端启停一个技能 → 在 chat 前台发起对话验证该技能未被加载 → 重载后状态刷新
