# ARCH-REVIEW-20260430-005 Skills 升级可执行清单（003+004 合并版）

- 评审日期：2026-04-30
- 来源：`ARCH-REVIEW-20260430-003`、`ARCH-REVIEW-20260430-004`
- 目标：将升级方案转为“可实施、可验收、可排期”的执行清单。

### 一、可落地性结论
- 结论：有条件可落地（可直接进入实施）。
- 依据：
  1. 主链路能力已具备（Tool Calling + Auto Continue）。
  2. 关键遗漏已识别并可通过增量改造补齐（契约/容量/稳定性/安全/测试）。
  3. 可以在兼容模式下分阶段上线，不阻断现有 `knowledge.search` 与 `attachment.context`。

### 二、关键问题与调整建议（可执行）
1. 问题：技能契约未字段级标准化
   - 位置：003-二-问题2/3，004-二-问题1
   - 风险：多技能返回结构不一致，续跑与前端展示不稳定
   - 建议：冻结统一 ToolResult 契约（P0）
     - 必填字段：`success`、`data`、`error`、`meta.skillId`、`meta.version`、`meta.latencyMs`
     - 验收：2 个核心技能返回结构 100% 符合契约测试
   - 优先级：P0
   - 负责人：后端（待指定）

2. 问题：技能包规范未落地
   - 位置：003-二-问题2
   - 风险：无法复用、无法分发、无法独立演进
   - 建议：落地最小 skills 包规范（P0）
     - 目录：`skills/<name>/SKILL.md` + 可选 `scripts/references/assets`
     - Frontmatter 最小字段：`name`、`description`、`version`、`entry`
     - 验收：本地扫描可加载 2 个示例包并注册成功
   - 优先级：P0
   - 负责人：后端（待指定）

3. 问题：版本治理缺失
   - 位置：003-二-问题3
   - 风险：灰度、回滚不可控
   - 建议：实现 `skill_id + version + status + checksum`（P0）
     - 支持 `latest` 与固定版本，生产默认固定版本
     - 验收：版本切换与回滚演练各 1 次成功
   - 优先级：P0
   - 负责人：后端/运维（待指定）

4. 问题：性能容量无门槛
   - 位置：004-二-问题2
   - 风险：引入技能后对话时延抖动
   - 建议：定义并验收 SLO（P0）
     - 技能路由开销 P95 <= 30ms
     - 单技能默认超时 3s（可配置）
     - 压测基线 50 QPS / 200 并发
   - 优先级：P0
   - 负责人：后端/测试（待指定）

5. 问题：稳定性策略未固化
   - 位置：004-二-问题3
   - 风险：外部技能失败放大
   - 建议：补齐重试/熔断/降级/回滚（P0）
     - 重试：幂等错误最多 2 次（指数退避）
     - 熔断：按技能失败率触发，半开探测恢复
     - 降级：技能失败不中断主回复
     - 验收：故障注入测试通过
   - 优先级：P0
   - 负责人：后端（待指定）

6. 问题：安全与合规边界不清
   - 位置：004-二-问题4
   - 风险：脚本执行越权与数据泄露
   - 建议：建立安全基线（P0）
     - 脚本白名单+沙箱约束（文件系统/网络）
     - 秘钥按 skill scope 注入
     - 审计最小字段：tenant/session/skill/version/inArgsHash/outHash
     - 验收：安全检查清单全绿
   - 优先级：P0
   - 负责人：后端/安全（待指定）

7. 问题：测试与发布门槛不完整
   - 位置：004-二-问题5
   - 风险：回归风险高
   - 建议：建立发布闸门（P0）
     - 契约测试 + 回归测试 + 压测 + 灰度门槛
     - 灰度节奏：5% → 25% → 100%
     - 回滚触发：错误率>1% 或 P95 超阈值持续 5 分钟
   - 优先级：P0
   - 负责人：测试/运维（待指定）

### 三、最小落地路径（MVP）
- 第一步：冻结契约与包规范（ToolResult + SKILL.md 字段）
- 第二步：实现兼容层（SkillProvider）与本地包加载
- 第三步：实现版本治理与安全基线
- 第四步：接入观测指标与发布闸门，灰度上线

### 四、待拍板决策
1. 生产环境是否禁止 `latest`（建议禁止）
2. 热加载是否纳入 P0（建议 P1，P0 先冷加载）
3. 沙箱方案选型：进程隔离还是容器隔离
4. `entry` 是否允许脚本与 Java provider 混合
