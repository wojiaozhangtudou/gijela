# ARCH-REVIEW-20260508-001

## 一、可落地性结论
- 结论：有条件可落地。
- 依据：
  - 基于 [CHANGELOG-token-consumption-metrics.md](./CHANGELOG-token-consumption-metrics.md)「核心改动」已覆盖 SDK 解析、编排透传、ES 聚合与前端展示主链路。
  - 运行期已验证流式天气工具链路可走通；但非流式链路仍受 embedding 依赖不可用影响，需明确降级策略后才能判定“完全可落地”。

## 二、关键问题与调整建议
1. 问题：需求文档未冻结“流式/非流式”在知识检索依赖不可用时的统一行为。
   - 位置：概述 + 核心改动/后端 2（聊天编排层）。
   - 风险：同一问题在两个入口表现不一致，前端与运维难以解释“为什么有时可答、有时失败”。
   - 建议：新增“4. 失败降级契约”，明确 embedding 不可用时默认降级为“跳过知识检索继续主回答”，并记录 `degraded=true` 审计字段。
   - 优先级：P0。

2. 问题：指标口径只定义了 `totalTokens` 聚合，缺少跨页面统一口径说明。
   - 位置：核心改动/后端 3、前端 3 与前端 4。
   - 风险：看板 KPI、告警阈值、报表导出可能出现口径不一致（窗口、去重、空值处理不同）。
   - 建议：新增“5. 指标口径冻结表”，至少固化：时间窗口、聚合维度、空值策略、重复事件去重策略。
   - 优先级：P0。

3. 问题：技能注册来源规则与热重载策略未写入文档。
   - 位置：核心改动（未覆盖）。
   - 风险：后续回归时容易再次出现 duplicate provider 告警，且难以定位为“来源标记冲突”。
   - 建议：新增“6. 技能来源与热重载约束”：
     - 本地包技能必须视为 `LOCAL`；
     - 业务内置注册采用“同名已存在即跳过”；
     - reload 只清理 `LOCAL`，`MCP` 走 replace。
   - 优先级：P1。

4. 问题：可观测性文档未给出运行期验收门槛。
   - 位置：验证清单。
   - 风险：只有“编译/测试通过”，缺少“日志侧无关键告警”的验收标准。
   - 建议：新增“7. 运行验收门槛”：
     - 连续两个热重载周期无 `duplicate provider name`；
     - ES 写入无 `Unable to parse response body`；
     - 流式请求可观测到 usage 与 tool 事件完整链路。
   - 优先级：P1。

## 三、最小落地路径（MVP）
- 第一步：冻结失败降级契约（流式/非流式一致），并补一条端到端回归用例。
- 第二步：冻结 `totalTokens` 指标口径，并把看板与告警引用到同一口径定义。
- 第三步：固化技能来源与热重载规则，纳入发布前运行验收清单。

## 四、待拍板决策
1. embedding 依赖不可用时，是否强制降级继续回答（而不是直接报错）。
2. `totalTokens` 告警是否按租户/模型双维度区分阈值。
3. 生产环境是否保留本地 Java 技能包扫描，或仅允许 MCP + 内置。
4. 运行验收是否把“关键告警为 0”设为上线硬门槛。
