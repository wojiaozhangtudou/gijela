# ARCH-REVIEW-20260506-012

## 一、可落地性结论
- 结论：**可落地**。
- 依据：功能、治理、排期、Jira 拆解已齐备；当前关键是上线前执行统一检查单，确保 Go/No-Go 判断一致。

## 二、关键问题与调整建议

1. 问题：上线前检查项分散在多个文档。
   - 位置：第1章 1.1（目标与范围一致性）
   - 风险：遗漏关键项（回滚、审批、灰度）。
   - 建议：使用单一发布检查单并要求逐项签字确认。
   - 优先级：P0

2. 问题：缺少明确否决条件。
   - 位置：第5章 5.1（稳定性）
   - 风险：带病发布。
   - 建议：设置 No-Go 条件：
     - 回滚演练失败
     - 冲突处理不可用
     - 审计字段缺失
   - 优先级：P0

3. 问题：灰度发布后缺少观测窗口标准。
   - 位置：第4章 4.1（性能与容量）
   - 风险：异常未及时发现。
   - 建议：规定灰度观察窗口 ≥ 30 分钟，指标超阈值立即回滚。
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步：按第六章检查单完成发布前自检。
- 第二步：召开 15 分钟 Go/No-Go 评审会，确认签字项。
- 第三步：按灰度策略发布并执行观察窗口。

## 四、待拍板决策
1. 首次发布灰度比例（建议：10%）。
2. 观察窗口长度（建议：30~60 分钟）。
3. 告警触发后是否自动回滚（建议：先人工）。

## 五、发布前最终检查单（逐项打勾）

### 5.1 功能正确性
- [ ] 系统级提示词读取/草稿保存/发布接口可用。
- [ ] 会话级提示词更新接口可用。
- [ ] 会话后续消息命中会话级提示词，历史消息不受影响。

### 5.2 协议与契约
- [ ] `ApiResponse` 结构一致。
- [ ] `PROMPT_VERSION_CONFLICT`（409）可复现且返回最新版本载荷。
- [ ] `PROMPT_FORBIDDEN` / `PROMPT_SENSITIVE_BLOCKED` 语义正确。

### 5.3 稳定性与回滚
- [ ] 回滚接口可将发布版本从 N 回到 N-1。
- [ ] 回滚演练耗时 ≤ 10 分钟。
- [ ] 灰度开关关闭时系统行为与旧版本一致。

### 5.4 安全与合规
- [ ] 权限点生效：`prompt.system.read/write`、`prompt.session.write`。
- [ ] 审批链路生效（若开启）：提交人与审批人不同。
- [ ] 审计记录包含操作者、前后版本、变更时间、diff 摘要。

### 5.5 观测与告警
- [ ] 日志/审计可查询 `effectivePromptHash`。
- [ ] 可按 `promptPublishedVersion` 统计错误率与延时。
- [ ] 告警阈值已配置并触发验证通过。

### 5.6 测试与质量门槛
- [ ] 后端测试通过：`mvn -pl gijela-core-chat -am test`。
- [ ] 前端构建通过（chat 前端模块）。
- [ ] 核心联调用例通过（系统级、会话级、冲突、回滚、灰度）。

## 六、Go/No-Go 判定规则
- **Go**：上述检查项全部勾选完成，且无 P0 缺陷。
- **No-Go**：任一 P0 失败（冲突不可用、回滚失败、审计缺失）即停止发布。
