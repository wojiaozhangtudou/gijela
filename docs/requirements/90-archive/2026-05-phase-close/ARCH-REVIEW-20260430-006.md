# ARCH-REVIEW-20260430-006 Skills 升级实施任务拆分（按角色）

- 评审日期：2026-04-30
- 来源：`ARCH-REVIEW-20260430-005`
- 目标：将可执行清单转为可派工任务，明确前后依赖、产出物与验收标准。

### 一、可落地性结论
- 结论：可落地（已满足实施前置条件，可进入开发排期）。
- 依据：
  1. P0 范围明确（契约、包规范、版本治理、稳定性、安全、测试闸门）。
  2. 任务可按角色并行，但存在关键串行依赖（契约冻结 → 开发实现 → 测试与灰度）。

### 二、关键问题与调整建议（按角色拆分）
1. 后端任务包（BE-P0）
   - 位置：005-问题1/2/3/5/6
   - 风险：若先编码后定契约，会导致返工。
   - 建议：
     - BE-1：冻结 `ToolResult` 契约（字段+错误码）
     - BE-2：实现 `SkillProvider` 兼容层（保留 legacy）
     - BE-3：实现本地 `skills/` 扫描与 `SKILL.md` 解析
     - BE-4：实现 `skill_id/version/status/checksum` 版本解析
     - BE-5：实现超时/重试/熔断/降级
     - BE-6：实现审计字段最小集与指标埋点
   - 优先级：P0

2. 前端任务包（FE-P0/P1）
   - 位置：005-问题1/7
   - 风险：后端契约变化未同步，导致展示错配。
   - 建议：
     - FE-1：按新 `ToolResult` 契约更新 tool result 展示
     - FE-2：新增技能版本与状态可视（可放 P1）
     - FE-3：失败降级文案统一（“技能失败但主回复继续”）
   - 优先级：P0（FE-1/FE-3），P1（FE-2）

3. 测试任务包（QA-P0）
   - 位置：005-问题7
   - 风险：无门槛直接上线风险高。
   - 建议：
     - QA-1：契约测试（2 个核心技能）
     - QA-2：回归测试（knowledge.search / attachment.context 全链路）
     - QA-3：故障注入测试（超时、熔断、降级）
     - QA-4：压测（50 QPS / 200 并发）
   - 优先级：P0

4. 运维与安全任务包（OPS/SEC-P0）
   - 位置：005-问题3/6/7
   - 风险：版本切换和沙箱策略未落地会阻断生产发布。
   - 建议：
     - OPS-1：灰度发布通道（5%→25%→100%）
     - OPS-2：回滚脚本与触发器（错误率/延迟阈值）
     - SEC-1：脚本白名单与沙箱配置（文件系统/网络）
     - SEC-2：秘钥 scope 下发策略
   - 优先级：P0

### 三、最小落地路径（MVP 实施顺序）
- 第一步：契约冻结（BE-1 + FE 对齐评审）
- 第二步：后端核心改造（BE-2/3/4/5）
- 第三步：前端适配（FE-1/FE-3）
- 第四步：测试闸门（QA-1/2/3/4）
- 第五步：灰度与回滚演练（OPS-1/2 + SEC-1/2）
- 第六步：全量上线与复盘
