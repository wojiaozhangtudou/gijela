# DEV-FEEDBACK-20260428-005 流式取消回放测试时间窗过窄

## 问题分类
- 实现风险

## 问题位置
- 需求/架构位置：`REQ-20260427-002` 第四章（可测试性）
- 涉及文件：
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/test/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClientStreamFunctionCallingTest.java`

## 影响范围
- 功能：无直接业务功能影响。
- 稳定性：测试将 SSE body 节流设置得过慢，首个 `DELTA` 在超时时间内无法稳定到达，导致取消回放测试误报失败。

## 严重级别
- Minor

## 现象
- 单测 `shouldStopReadingAfterClose()` 首次执行失败，`firstDeltaLatch.await(5s)` 超时。
- 根因不是主链路代码错误，而是测试节流参数 `1 byte / 120ms` 导致首条事件传输时间过长。

## 修正建议
- 将节流参数调整为“首条事件可及时到达，但第二条事件仍有足够关闭窗口”的区间。
- 后续流式回放测试统一避免极端字节级节流配置，优先验证业务语义而非网络极限抖动。

## 临时绕行方案
- 无（已在测试中修复）。

## 处理结果
- 已将取消回放测试节流调整为 `32 bytes / 200ms`。
- 已重新执行 `openai-compatible` 模块测试，`Tests run: 7, Failures: 0, Errors: 0`。
- 结论：该反馈项已闭环。
