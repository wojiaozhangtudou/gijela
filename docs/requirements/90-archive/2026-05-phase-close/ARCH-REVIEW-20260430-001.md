# ARCH-REVIEW-20260430-001 附件渐进式摘要提炼（文件 → LLM → 三层内容）架构评审

- **评审日期：** 2026-04-30
- **需求来源：** 用户提议，对话框附件上传后自动提炼摘要，以渐进式披露方式供大模型加载

---

## 一、可落地性结论

- **结论：有条件可落地**
- **依据：** 核心链路（文件解析 → LLM 提炼 → 渐进存储）技术栈均已具备（OkHttp LLM 调用、S3 存储、MyBatis-Plus 持久化），但需明确异步处理边界、LLM 调用成本控制及前端消费协议。

---

## 二、关键问题与调整建议

### 1. sessionId 强制必填
- **位置：** `ChatController.upload()` + `DefaultAttachmentService`
- **风险：** 当前前端在对话建立前就可能上传文件，强制 sessionId 会破坏现有流程
- **建议：** 上传接口新增校验，`sessionId` 为空时直接返回 4xx 错误；前端需保证先建会话再上传
- **优先级：P0**

### 2. 文件内容提取
- **位置：** 新增 `FileContentExtractor` 组件
- **风险：** 不同文件类型（PDF/Word/txt/md）解析库不同，PDF 解析有依赖包体积问题
- **建议：** 第一阶段只支持 `.txt` / `.md`；PDF/Word 引入 Apache Tika（通用解析），单独 P1
- **优先级：P0（txt/md）、P1（PDF/Word）**

### 3. LLM 提炼必须异步
- **位置：** 上传接口不能同步等 LLM 返回
- **风险：** 同步调用导致接口超时（30s+）、线程池耗尽
- **建议：** 上传接口立即返回（含 `attachmentId`），后台异步执行两次 LLM 调用（`原文 → 浓缩MD → 摘要`），写入 `chat_attachment` 扩展字段；前端轮询处理状态
- **优先级：P0**

### 4. chat_attachment 表结构扩展
- **位置：** `chat_attachment` DDL
- **风险：** 当前表只存 objectKey，无法承载三层内容
- **建议：** 新增字段：
  ```sql
  raw_text       LONGTEXT        -- 提取的原始文本
  condensed_md   LONGTEXT        -- LLM 浓缩后的 Markdown
  summary        VARCHAR(500)    -- 一句话摘要
  process_status TINYINT DEFAULT 0  -- 0=待处理 1=处理中 2=完成 3=失败
  ```
- **优先级：P0**

### 5. LLM 渐进加载协议
- **位置：** Chat 对话流程 prompt 组装
- **风险：** 三层内容如何选择注入 prompt 无规则
- **建议：** 按 token 预算决策：默认注入 `summary`；追问详细时注入 `condensed_md`；明确要求原文时注入 `raw_text`（或给对象存储 URL）
- **优先级：P1**

---

## 三、最小落地路径（MVP）

- **第一步（接口层）：** upload 接口强制校验 sessionId 非空，立即返回 `{ attachmentId, status: 0 }`
- **第二步（内容提取）：** 新增 `FileContentExtractor`，先支持 txt/md；上传后异步提取原始文本写入 `raw_text`，`status=1`
- **第三步（LLM 提炼）：** 第一次 LLM 调用 `raw_text → condensed_md`（压缩到30%）；第二次 `condensed_md → summary`（50字以内）；写入对应字段，`status=2`
- **第四步（状态查询接口）：** `GET /api/v1/chat/attachments/{attachmentId}/status`，返回 `{ status, summary, condensedMd? }`；前端轮询直到 `status=2`
- **第五步（prompt 注入）：** 对话时将 summary 注入 system/context，按需升级加载层级

## 四、待拍板决策

1. **原始文本存哪里**？写 DB `raw_text` 字段（简单但 DB 膨胀）还是仍存对象存储、DB 只存引用（推荐大文件）？
2. **LLM 提炼失败如何处理**？静默忽略（对话时不注入）还是提示用户重试？
3. **浓缩 prompt 是否可配置**？不同场景（简历/合同/文章）提炼侧重点不同
4. **前端感知方式**：轮询 vs SSE？
5. **token 预算阈值**：什么条件下从 summary 升级到 condensed_md 注入？
