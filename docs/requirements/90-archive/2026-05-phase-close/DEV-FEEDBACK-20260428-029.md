# DEV-FEEDBACK-20260428-029 LLM 审计与 Chat 审计结果语义不一致

## 一、问题分类
- 架构缺口

## 二、问题位置
- 涉及文件：
  - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/adapter/llm/OpenAiChatAdapter.java`
  - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/service/impl/ChatOrchestratorServiceImpl.java`

## 三、影响范围
- 可维护性：同一调用链路下 `llm.*` 与 `chat.*` 审计结果结构不同，后续统计聚合复杂。
- 稳定性：异常路径缺乏统一口径，不利于故障定位与告警规则沉淀。

## 四、严重级别
- Major

## 五、问题说明
- 原先 `llm.complete` 仅记录 `finishReason`，而 `chat.complete/chat.stream` 已采用 `SUCCESS/ERROR` 语义。
- 缺乏统一耗时字段，导致跨层对比难以自动化。

## 六、修正建议
1. 统一 `llm.complete`、`llm.stream` 结果格式，增加 `latencyMs`。
2. 补齐 `llm.complete` 异常路径审计，保证成功/失败都可观测。
3. 维持字段长度边界，避免审计落库噪音。

## 七、临时绕行方案
- 无需绕行，本轮已修复。

## 八、处理结果
- 已修复：
  - `llm.complete` 成功：`SUCCESS;finishReason=<x>;latencyMs=<n>`
  - `llm.complete` 失败：`ERROR:<msg>;latencyMs=<n>`
  - `llm.stream` 终态：成功/失败均记录统一格式并带 `latencyMs`
- 已验证通过：
  - `mvn -pl gijela-core-chat "-Dtest=ChatControllerTest,ChatOrchestratorServiceImplTest,ChatHistoryQueryServiceImplTest,RedisConversationStoreTest,InMemoryConversationStoreTest" test`
- 当前状态：已关闭。
