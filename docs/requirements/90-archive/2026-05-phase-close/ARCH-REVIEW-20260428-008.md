# ARCH-REVIEW-20260428-008 chat 模块最终开发基线评审

### 一、可落地性结论
- 结论：可直接交付开发。
- 依据：
  - 模块边界、协议方向、基础设施映射、附件存储与默认值已完成连续评审收敛。
  - 当前剩余事项不再影响开发启动，均可在开发中按已冻结基线执行。

### 二、关键问题与调整建议
1. 问题：开发启动前缺少“一页式基线清单”。
   - 位置：前序评审文档分散在 `001~007`。
   - 风险：开发需要来回翻文档，容易遗漏默认决策。
   - 建议：冻结以下开发基线为唯一执行版本：
     - 后端新模块：`gijela-core-chat`
     - 前端新模块：`gijela-bloom-chat`
     - `gijela-core-chat` 独立端口部署
     - `gijela-bloom-chat` 复用 `pistil` 登录态
     - 流式消费：`fetch + ReadableStream`
   - 优先级：P0

2. 问题：同步/流式接口虽已收敛，但未在最终基线中并列列出。
   - 位置：前序 `002/003` 评审。
   - 风险：开发可能误增并行接口。
   - 建议：冻结仅 2 条主接口：
     - `POST /api/v1/chat/completions`
     - `POST /api/v1/chat/stream`
   - 优先级：P0

3. 问题：基础设施映射虽已评审，但需升格为开发基线。
   - 位置：前序 `005/006/007` 评审。
   - 风险：开发阶段再次出现“放 Redis 还是 MySQL”的重复讨论。
   - 建议：冻结为：
     - Redis：会话态、最近消息、上下文摘要、SSE 会话状态
     - MySQL：会话元数据、历史消息、审计记录、附件元数据
     - Qdrant：知识检索
     - RustFS(S3)：附件对象存储
   - 优先级：P0

4. 问题：默认值已形成，但需最终固化。
   - 位置：前序 `007` 评审。
   - 风险：开发时各自取值不同。
   - 建议：冻结默认值：
     - `chat_message` 全量落 MySQL
     - Redis 最近消息保留 20 轮
     - 上下文摘要每 10 轮或 token 超过 `6000` 刷新
     - 独立 `chat_audit_log`
     - Qdrant 共享 collection + tenant filter
     - RustFS object key：`tenant/session/yyyyMMdd/uuid.ext`
   - 优先级：P0

5. 问题：技能与 MCP 范围需要开发基线化。
   - 位置：前序 `002/003` 评审。
   - 风险：首期范围膨胀。
   - 建议：首期仅做：
     - 内置 Skills：`time.now`、`echo`
     - MCP mock：`knowledge.search`
   - 优先级：P0

6. 问题：组件清单需要冻结到可拆任务粒度。
   - 位置：前序 `003/006` 评审。
   - 风险：多人开发边界不清。
   - 建议：后端至少创建：
     - `ChatController`
     - `ChatOrchestratorService`
     - `ConversationStore`
     - `InMemoryConversationStore`（MVP 默认实现，预留 Redis 实现）
     - `OpenAiChatAdapter`
     - `SkillRegistry`
     - `McpGateway`
     - `ObjectStorageGateway`
     - `AttachmentService`
     - `KnowledgeSearchGateway`
     - `ChatAuditService`
     - `SseSessionRegistry`
   - 优先级：P0

7. 问题：开发顺序若不冻结，容易并行失控。
   - 位置：前序 `006` 评审。
   - 风险：先做附件或检索，主链路迟迟不闭环。
   - 建议：实施顺序固定为：
     1. MySQL 表 + Redis key 规范
     2. 同步接口
     3. 流式接口
     4. Skills/MCP mock
     5. RustFS 附件
     6. Qdrant 检索
   - 优先级：P0

### 三、最小落地路径（MVP）
- 第一步：建模块骨架与依赖
  - `gijela-core-chat`
  - `gijela-bloom-chat`
- 第二步：打通主链路
  - `/chat/completions`
  - `/chat/stream`

- 第三步：补扩展链路
  - Skills/MCP mock
  - RustFS 附件
  - Qdrant 检索
