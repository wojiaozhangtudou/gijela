# ARCH-REVIEW-20260506-017

## 一、可落地性结论
- 结论：有条件可落地。
- 依据：
  - 提示词配置主链路（系统级/会话级 CRUD、冲突处理、前端编辑）已具备运行能力。
  - 当前缺口主要在“数据库初始化与迁移落盘”及“上线文档同步”，属于可补齐项，不涉及架构推倒。

## 二、关键问题与调整建议
1. 问题：数据库迁移脚本未落盘，环境初始化存在漂移风险。
   - 位置：第5章 条目5.1/5.2/5.3（ARCH-REVIEW-20260506-005）
   - 风险：新环境仅执行既有 migration 时无法创建 `chat_prompt_system` / `chat_prompt_system_audit` / `chat_session_prompt`，导致接口运行时表不存在。
   - 建议：新增 Flyway 脚本 `V7__chat_prompt_config.sql`，一次性创建三张提示词表并补齐索引、唯一约束。
   - 优先级：P0

2. 问题：基础建表脚本未包含提示词表，离线初始化不可复用。
   - 位置：第6章 条目6.1（ARCH-REVIEW-20260506-006）
   - 风险：非 Flyway 路径初始化（如本地快速建库）会缺失提示词表，造成环境行为不一致。
   - 建议：同步更新 `db/chat-schema.sql`，加入提示词三表定义，保持与 migration 一致。
   - 优先级：P1

3. 问题：冲突提示后的可观察性信息不足（版本与时间不直观）。
   - 位置：第8章 条目8.2（ARCH-REVIEW-20260506-008）
   - 风险：操作者无法快速确认自己编辑基线，重试成本高。
   - 建议：前端抽屉展示草稿/发布/会话版本与时间字段，冲突刷新后直接可见。
   - 优先级：P1

4. 问题：提示词控制器缺少独立单测，回归风险偏高。
   - 位置：第3章 条目3.4（ARCH-REVIEW-20260506-006）
   - 风险：租户头、操作人回退、会话查询接口改动时缺少快速防线。
   - 建议：新增 `ChatPromptControllerTest`，覆盖 `getSystemCurrent`、`getSessionPrompt`、`saveSystemDraft`、`updateSessionPrompt`。
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步：落盘 `V7__chat_prompt_config.sql`，确保迁移可执行。
- 第二步：同步 `chat-schema.sql`，确保初始化脚本一致。
- 第三步：补前端版本/时间展示与控制器单测，形成“可操作 + 可回归”闭环。

## 四、待拍板决策
1. 生产发布采用“仅 Flyway 迁移”还是“允许 `chat-schema.sql` 初始化 + 增量 migration”双路径。
2. `chat_prompt_system_audit.before_content/after_content` 长期保留策略（全量保留或按周期归档）。
3. 会话提示词是否纳入后台审计看板（当前仅系统级含显式审计表）。
