# DEV-FEEDBACK-20260428-024 Mockito 动态 Agent 警告的未来兼容风险

## 一、问题分类
- 实现风险

## 二、问题位置
- 涉及文件：
  - `gijela-core/gijela-core-chat/pom.xml`
  - `gijela-core/gijela-core-chat/src/test/java/com/gijela/morpheus/chat/controller/ChatControllerTest.java`
- 触发场景：
  - 执行最小闭环关键测试集时，Mockito inline mock maker 通过“self-attaching”方式动态加载 ByteBuddy Agent，JDK 输出未来版本将默认禁用该能力的警告。

## 三、影响范围
- 测试稳定性：未来 JDK 默认策略收紧后，单测可能在本地或 CI 环境失败。
- 可维护性：持续出现高噪音警告，影响测试日志可读性和异常定位效率。

## 四、严重级别
- Minor

## 五、问题说明
- 当前关键测试集可以通过，但日志提示：动态加载 Java Agent 在未来 JDK 版本中将被默认禁止。
- 这不是当前阻塞项，但属于“版本演进下的潜在失败点”。

## 六、修正建议
1. 在 surefire/failsafe 统一配置 Mockito 相关 JVM 参数，避免依赖运行时自附着默认策略。
2. 在 CI 增加“JDK 升级兼容性预检”任务（可按周/按版本触发），提前暴露风险。
3. 记录并固化测试 JVM 参数规范，避免开发机与 CI 行为不一致。

## 七、临时绕行方案
- 不再需要临时绕行；已落地最小修正。

## 八、处理结果
- 已完成修复：在 `gijela-core-chat/pom.xml` 增加 `maven-surefire-plugin` 配置，注入 JVM 参数 `-XX:+EnableDynamicAgentLoading`。
- 已完成验证：执行关键测试集 `mvn -pl gijela-core-chat "-Dtest=ChatControllerTest,ChatHistoryQueryServiceImplTest,RedisConversationStoreTest" test` 通过，且 Mockito 动态 Agent 警告不再出现。
- 当前状态：已关闭。
