# ARCH-REVIEW-20260506-006

## 一、可落地性结论
- 结论：**可落地**。
- 依据：当前 `gijela-core-chat` 已有会话、消息、审计、统一响应与前端 `gijela-bloom-chat` 对话页链路；在不破坏现有接口的前提下，新增“系统级提示词 + 会话级提示词”可按增量方式落地。

## 二、关键问题与调整建议

1. 问题：后端缺少提示词领域对象与持久化层。
   - 位置：第2章 2.1（架构边界与模块职责）
   - 风险：提示词逻辑散落在 Controller/Orchestrator，后续不可维护。
   - 建议：新增以下文件（P0）：
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/domain/entity/ChatPromptSystem.java`
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/domain/entity/ChatPromptSystemAudit.java`
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/domain/entity/ChatSessionPrompt.java`
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/mapper/ChatPromptSystemMapper.java`
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/mapper/ChatPromptSystemAuditMapper.java`
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/mapper/ChatSessionPromptMapper.java`
   - 优先级：P0

2. 问题：接口入口未隔离，容易污染 `ChatController`。
   - 位置：第2章 2.2（协议与数据契约）
   - 风险：`ChatController` 继续膨胀，变更风险升高。
   - 建议：新增独立控制器（P0）：
     - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/controller/ChatPromptController.java`
     - 路由：
       - `GET /api/v1/chat/prompts/system/current`
       - `PUT /api/v1/chat/prompts/system/draft`
       - `POST /api/v1/chat/prompts/system/publish`
       - `PUT /api/v1/chat/sessions/{sessionId}/prompt`
   - 优先级：P0

3. 问题：编排层尚未接入有效提示词拼接。
   - 位置：第3章 3.1（稳定性与一致性）
   - 风险：前端改了提示词但模型调用不生效。
   - 建议：在 `ChatOrchestratorServiceImpl` 注入提示词解析服务（P0）：
     - 修改：`gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/service/impl/ChatOrchestratorServiceImpl.java`
     - 新增：`PromptResolveService`（负责 system/session/guardrail 拼接）
     - 在 `complete()` 与 `stream()` 两条链路统一注入 `effectivePrompt`。
   - 优先级：P0

4. 问题：前端缺少 API 与状态源，页面无法直接编辑。
   - 位置：第3章 3.2（前端实施）
   - 风险：临时在页面散写请求，后续难维护。
   - 建议：按现有 `src/api + src/store` 结构新增（P0）：
     - 新增：`gijela-bloom/gijela-bloom-chat/src/api/prompt.ts`
     - 新增：`gijela-bloom/gijela-bloom-chat/src/store/prompt.ts`
     - 修改：`gijela-bloom/gijela-bloom-chat/src/views/ChatPage.vue`（系统级抽屉 + 会话级面板）
   - 优先级：P0

5. 问题：权限与审计未闭环。
   - 位置：第4章 4.1（安全与合规）
   - 风险：越权编辑、无法回溯变更责任。
   - 建议：
     - 鉴权点：`prompt.system.read`、`prompt.system.write`、`prompt.session.write`
     - 审计写入 `ChatPromptSystemAudit`
     - 发布前执行敏感词扫描，失败返回 `PROMPT_SENSITIVE_BLOCKED`
   - 优先级：P0

6. 问题：上线门槛未量化。
   - 位置：第5章 5.1（可测试性与上线）
   - 风险：上线后提示词串租户或串会话。
   - 建议：
     - 单测：版本冲突、租户隔离、拼接顺序
     - 集成：会话改提示词后仅影响后续消息
     - 回滚：系统级按 `publishedVersion` 一键回退
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步：后端建表 + Entity/Mapper + `ChatPromptController` + `PromptResolveService`。
- 第二步：前端新增 `prompt.ts`（api/store），在 `ChatPage.vue` 接入编辑入口。
- 第三步：联调 `effectivePromptHash` 展示与审计回放，完成灰度发布。

## 四、待拍板决策
1. 系统级提示词是否允许按 `modelRoute` 多版本并行（建议：允许）。
2. 会话级提示词是否允许富文本（建议：仅纯文本，避免注入风险）。
3. 发布是否必须双人复核（建议：生产开启，测试关闭）。
