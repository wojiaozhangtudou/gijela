# ARCH-REVIEW-20260506-004

## 一、可落地性结论
- 结论：**有条件可落地**。
- 依据：你提出的“系统级提示词 + 会话级提示词 + 前端实时可改”方向正确，但当前需求缺少优先级合并规则、发布范围控制、审计与回滚设计；补齐后可直接进入开发。

## 二、关键问题与调整建议

1. 问题：目标与范围边界未冻结（全局生效 vs 指定模型/租户/应用生效）。
   - 位置：第1章 1.1（目标定义）
   - 风险：生产误改导致所有会话输出漂移，无法快速止损。
   - 建议：补充作用域三元组：`scopeType(system/session)` + `tenantId` + `modelRoute`，并声明默认仅对“当前应用 + 当前租户”生效；系统级改动需“草稿/发布”两阶段。
   - 优先级：P0

2. 问题：提示词合并顺序与冲突策略不明确。
   - 位置：第2章 2.1（协议与数据契约）
   - 风险：同一会话在不同入口调用时表现不一致，难以复现。
   - 建议：固定拼接链路：`系统级(已发布) -> 会话级(当前版本) -> 运行时安全护栏`；并增加 `effectivePromptHash` 回传字段用于排障与审计。
   - 优先级：P0

3. 问题：缺少最小接口契约，前端无法稳定落地“直接编辑”。
   - 位置：第2章 2.2（请求/响应）
   - 风险：页面先做了，后端接口反复改，联调成本高。
   - 建议：先冻结 4 个接口：
     - `GET /api/v1/chat/prompts/system/current`
     - `PUT /api/v1/chat/prompts/system/draft`
     - `POST /api/v1/chat/prompts/system/publish`
     - `PUT /api/v1/chat/sessions/{sessionId}/prompt`
     返回统一 `ApiResponse`，错误码新增 `PROMPT_VERSION_CONFLICT`、`PROMPT_FORBIDDEN`。
   - 优先级：P0

4. 问题：并发修改与版本冲突未设计。
   - 位置：第5章 5.1（稳定性）
   - 风险：多人同时编辑造成“后写覆盖前写”。
   - 建议：所有写接口引入 `version`（乐观锁）；冲突返回 409 + 最新版本摘要，前端弹“覆盖/合并/放弃”选择。
   - 优先级：P0

5. 问题：安全与合规缺少最小控制面。
   - 位置：第6章 6.1（鉴权审计）
   - 风险：越权改系统提示词、敏感指令入库无法追责。
   - 建议：
     - 权限拆分：`prompt.system.read`、`prompt.system.write`、`prompt.session.write`
     - 审计记录：操作者、变更前后 diff、会话ID、版本号、发布时间
     - 敏感词扫描：发布前阻断（如密钥、token、内网地址）
   - 优先级：P0

6. 问题：可测试性和上线门槛未定义。
   - 位置：第7章 7.1（测试与发布）
   - 风险：上线后提示词失效或串会话，回滚慢。
   - 建议：上线门槛最小集：
     - 单测：合并顺序、版本冲突、权限校验
     - 集成：编辑后新消息生效、历史消息不回写
     - 回滚：支持“按版本一键回滚系统级提示词”
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步：后端先落表与接口（系统级草稿/发布 + 会话级覆盖 + 乐观锁 + 审计）。
- 第二步：前端对话页增加“双提示词入口”（系统级抽屉、会话级面板），走 `src/api` 统一请求。
- 第三步：编排层接入 `effectivePrompt` 拼接与哈希回传，联调完成后开放灰度。

## 四、待拍板决策
1. 系统级提示词是否允许按“模型路由”差异化（建议：允许，默认跟随应用级）。
2. 会话级提示词是否支持模板变量（如用户名、时间）（建议：MVP 不支持，避免注入风险）。
3. 发布策略是否要求双人复核（建议：生产开启，测试环境关闭）。
