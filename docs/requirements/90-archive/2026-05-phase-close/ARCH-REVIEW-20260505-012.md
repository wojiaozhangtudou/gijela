  3. 当前已具备进入文件级实施的决策前置条件。

### 二、关键问题与调整建议
1. 问题：首版同步链路需要防止范围膨胀
   - 位置：接口契约与执行任务单
   - 风险：临时再引入异步任务、自动重试或弱幂等，会破坏当前冻结基线。
   - 建议：首版严格执行以下冻结值：
     - 抽取与导入均为同步接口；
     - 所有模式必须人工确认后入图；
     - `/import` 强制 `Idempotency-Key`；
     - 首版不建设 `/tasks/**`；
     - `PARTIAL_SUCCESS` 不自动重试。
   - 优先级：P0

2. 问题：同步首版的保护策略需保持最小必要
   - 位置：容量与安全边界
   - 风险：若保护不足，会导致前后端提示不一致；若保护过重，会引入无谓复杂度。
   - 建议：首版冻结为：
     - 文件 <= 10MB；文本 <= 50k；实体 <= 300；关系 <= 800；`maxTokens <= 4096`；
     - 错误码：`GRAPH_FILE_TOO_LARGE`、`GRAPH_TEXT_TOO_LONG`；
     - `promptOverride` 仅灰度账号 + `graph:debug-prompt` + 审计。
   - 优先级：P0

### 三、最小落地路径（MVP）
- 第一步：按冻结值更新 DTO/VO、错误码、Controller 契约。
- 第二步：落同步抽取、预览确认、幂等导入、批次补偿骨架。
- 第三步：前端实现同步交互与错误提示映射。

### 四、已确认决策
1. 已确认：首版同步链路不设置应用层超时阈值。
2. 已确认：新增错误码 `GRAPH_FILE_TOO_LARGE`、`GRAPH_TEXT_TOO_LONG`。
3. 已确认：`Idempotency-Key` 在 `/import` 为必填。
4. 已确认：`PARTIAL_SUCCESS` 不自动重试，必须再次人工确认。
5. 已确认：失败补偿按 `importBatchId` 批次执行。
