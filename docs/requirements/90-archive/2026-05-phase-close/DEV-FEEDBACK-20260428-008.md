# DEV-FEEDBACK-20260428-008 RuntimeOptions 类型化后上下文透传缺口

## 问题分类
- 实现风险

## 问题位置
- 需求/架构位置：`REQ-20260427-002` 第三章 P0-2（统一调用链路）与 P0-4（异常分层与可观测）
- 涉及文件：
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/OpenAiCompatibleClient.java`
  - `gijela-core/gijela-core-llm/gijela-core-llm-sdk-openai-compatible/src/main/java/com/gijela/morpheus/llm/sdk/openai/OpenAiRuntimeOptions.java`

## 影响范围
- 功能：工具调用默认 `ToolContext` 回退路径依赖 metadata 原始透传；缺失会影响上下文完整性。
- 稳定性：`OpenAiRuntimeOptions` 重构过程中曾出现编译中断，影响本迭代持续交付效率。

## 严重级别
- Major

## 现象
- 在将 `metadata` 解析类型化为 `OpenAiRuntimeOptions` 后，`OpenAiCompatibleClient` 中仍需要基于原始 metadata 构建默认 `ToolContext`。
- 初版 `OpenAiRuntimeOptions` 未保留原始 metadata，导致编译报错（缺少 `metadata()` 访问入口），并带来默认上下文信息丢失风险。

## 修正建议
- 在 `OpenAiRuntimeOptions` 中显式保留 `metadata` 字段，并在 `fromMetadata()` 中统一注入。
- `OpenAiCompatibleClient` 全链路改为传递 `OpenAiRuntimeOptions`，避免重复 map 解析与魔法字符串分散。

## 临时绕行方案
- 无需额外绕行；已在本轮完成代码修复并通过测试验证。

## 处理结果
- 已完成：
  - `OpenAiCompatibleClient` 的 `chat()/stream()` 及相关 helper 切换为 `OpenAiRuntimeOptions`。
  - `OpenAiRuntimeOptions` 新增原始 `metadata` 保留字段，用于默认 `ToolContext` 回退构建。
- 验证结果：
  - 执行 `mvn -pl gijela-core-llm/gijela-core-llm-sdk-openai-compatible -am test -DskipITs`
  - 结果：`Tests run: 25, Failures: 0, Errors: 0`，`BUILD SUCCESS`。
- 结论：该反馈项已闭环。
