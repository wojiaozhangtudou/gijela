# ARCH-REVIEW-20260506-014

## 一、可落地性结论
- 结论：**可落地**。
- 依据：发布前与发布日流程已完备，当前缺口是“发布后持续观测标准化”；补齐 7 天模板后可形成闭环治理。

## 二、关键问题与调整建议

1. 问题：发布后观察缺少统一口径。
   - 位置：第2章 2.1（目标与范围一致性）
   - 风险：团队对“是否稳定”判断不一致。
   - 建议：固定 7 天窗口，统一指标口径（错误率、P95、回滚次数、冲突率）。
   - 优先级：P0

2. 问题：缺少日报模板与责任分工。
   - 位置：第3章 3.1（可测试性与上线门槛）
   - 风险：问题记录不完整，复盘难追溯。
   - 建议：使用标准日报模板，固定 BE/FE/QA 三方签字。
   - 优先级：P0

3. 问题：周复盘缺少量化改进项。
   - 位置：第5章 5.1（稳定性）
   - 风险：同类问题重复出现。
   - 建议：周报必须包含“问题TOP3 + 根因 + 下周动作 + owner + 截止时间”。
   - 优先级：P1

## 三、最小落地路径（MVP）
- 第一步：上线后 D1~D7 按第六章日报模板填报。
- 第二步：每日 15 分钟站会同步异常与处置。
- 第三步：D7 输出周复盘并冻结改进计划。

## 四、待拍板决策
1. 观测窗口是否延长至 14 天（建议：首版 7 天）。
2. 指标阈值是否按租户分层（建议：先统一，后分层）。
3. 周复盘是否纳入发布准入基线（建议：纳入）。

## 五、7 天观测指标（固定口径）
1. `chat.complete` 错误率（日环比、周同比）。
2. `chat.stream` 错误率与中断率。
3. P95 响应时延（按 `promptPublishedVersion` 维度）。
4. `PROMPT_VERSION_CONFLICT` 触发率。
5. 回滚次数与平均恢复时长（MTTR）。
6. 灰度命中率与灰度租户反馈。
