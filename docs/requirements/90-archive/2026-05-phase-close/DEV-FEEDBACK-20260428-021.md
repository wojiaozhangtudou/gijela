# DEV-FEEDBACK-20260428-021 chat 基础设施落地缺少 DDL 与持久化契约

## 一、问题分类
- 架构缺口

## 二、问题位置
- 文档位置：
  - `ARCH-REVIEW-20260428-006`
  - `ARCH-REVIEW-20260428-007`
  - `ARCH-REVIEW-20260428-008`
- 涉及文件：
  - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/service/impl/InMemoryConversationStore.java`
  - `gijela-core/gijela-core-chat/src/main/java/com/gijela/morpheus/chat/service/impl/DefaultChatAuditService.java`

## 三、影响范围
- 功能：会话历史、审计日志、附件元数据尚未真正落 MySQL / Redis。
- 稳定性：服务重启后会话态丢失。
- 可维护性：后续切 Redis/MySQL 时仍需补一次持久化层改造。

## 四、严重级别
- Major

## 五、问题说明
- 当前评审基线已冻结：Redis 负责会话态/最近消息/摘要，MySQL 负责历史消息/审计/附件元数据。
- 但仓库中尚未提供 `chat_conversation`、`chat_message`、`chat_audit_log`、`chat_attachment` 等表结构与 Mapper/Repository 契约。
- 为保证主链路先可编译、可联调，本轮实现暂以 `InMemoryConversationStore` 和日志审计占位，未直接接入 Redis/MySQL 持久化。

## 六、修正建议
1. 补齐 chat 模块 DDL：
   - `chat_conversation`
   - `chat_message`
   - `chat_audit_log`
   - `chat_attachment`
2. 明确 Redis key 规范：
   - 最近消息 key
   - 摘要 key
   - SSE 会话状态 key
3. 冻结 Mapper/Entity 字段最小集合，并补充建表脚本到仓库。
4. 下一轮优先将 `ConversationStore` 切为 Redis 实现，并补 MySQL 审计/消息落盘。

## 七、临时绕行方案
- 已不需要临时绕行；本轮已完成持久化契约补齐。

## 八、处理结果
- 已补齐 DDL：`gijela-core/gijela-core-chat/src/main/resources/db/chat-schema.sql`，包含 `chat_conversation`、`chat_message`、`chat_audit_log`、`chat_attachment`。
- 已补齐 Entity/Mapper 契约：
  - `ChatConversation` / `ChatConversationMapper`
  - `ChatMessageEntity` / `ChatMessageMapper`
  - `ChatAuditLog` / `ChatAuditLogMapper`
  - `ChatAttachment` / `ChatAttachmentMapper`
- 已完成实现切换：
  - 会话存储默认 `gijela.chat.conversation.store=redis`，并在 `ChatModuleConfig` 中装配 `RedisConversationStore`。
  - 审计落盘装配 `MySqlChatAuditService`。
  - Redis 不可用时保留降级兜底，不阻断主链路。
- 已验证：chat 关键测试集通过（`ChatControllerTest`、`ChatHistoryQueryServiceImplTest`、`RedisConversationStoreTest`）。
- 当前状态：已关闭。
