# ARCH-REVIEW-20260506-005

## 一、可落地性结论
- 结论：**可落地**。
- 依据：在 [ARCH-REVIEW-20260506-004](./ARCH-REVIEW-20260506-004.md) 的 P0 约束基础上，当前已可冻结“表结构 + API 契约 + 前端交互最小集”，可直接进入开发。

## 二、关键问题与调整建议

1. 问题：缺少可执行的数据模型定义。
   - 位置：第2章 2.1（协议与数据契约）
   - 风险：后端实现与前端字段不一致。
   - 建议：先冻结 3 张核心表（P0）：
     - `chat_prompt_system`（系统级提示词，草稿与发布）
     - `chat_prompt_system_audit`（系统级变更审计）
     - `chat_session_prompt`（会话级提示词）
   - 优先级：P0

2. 问题：缺少统一错误码与并发冲突语义。
   - 位置：第2章 2.2（错误契约）
   - 风险：前端无法稳定处理冲突提示。
   - 建议：新增错误码：
     - `PROMPT_VERSION_CONFLICT`（409）
     - `PROMPT_FORBIDDEN`（403）
     - `PROMPT_SENSITIVE_BLOCKED`（400）
   - 优先级：P0

3. 问题：前端交互未冻结，容易后改。
   - 位置：第3章 3.1（前端实施）
   - 风险：页面先做后返工。
   - 建议：先落地“对话页双入口”：
     - 系统级：抽屉（只读当前发布 + 可编辑草稿）
     - 会话级：侧边面板（当前会话覆盖）
   - 优先级：P0

## 三、最小落地路径（MVP）
- 第一步：建表 + Mapper + Service（含乐观锁与审计写入）。
- 第二步：开放 4 个 API 并完成权限校验。
- 第三步：前端接入并在发送消息时回传 `effectivePromptHash`。

## 四、待拍板决策
1. 系统级提示词发布是否需要审批流（建议：MVP 否，生产可配置）。
2. 系统级是否允许“按模型路由发布多版本”（建议：允许，默认继承应用级）。

## 五、数据表草案（可直接建表）

### 5.1 `chat_prompt_system`

建议主键：`id BIGINT`，唯一键：`uk_scope(tenant_id, app_code, model_route)`

字段：
- `id`
- `tenant_id` VARCHAR(64)
- `app_code` VARCHAR(64)
- `model_route` VARCHAR(128)
- `draft_content` TEXT
- `draft_version` BIGINT
- `published_content` TEXT
- `published_version` BIGINT
- `published_at` DATETIME
- `published_by` BIGINT
- `updated_at` DATETIME
- `updated_by` BIGINT
- `created_at` DATETIME
- `created_by` BIGINT
- `deleted` TINYINT(1)

说明：
- 草稿编辑只改 `draft_*`。
- 发布时复制 `draft_content -> published_content` 并 `published_version + 1`。

### 5.2 `chat_prompt_system_audit`

字段：
- `id` BIGINT
- `tenant_id` VARCHAR(64)
- `app_code` VARCHAR(64)
- `model_route` VARCHAR(128)
- `action` VARCHAR(32)（`SAVE_DRAFT`/`PUBLISH`/`ROLLBACK`）
- `before_version` BIGINT
- `after_version` BIGINT
- `before_content` MEDIUMTEXT
- `after_content` MEDIUMTEXT
- `operator_id` BIGINT
- `operator_name` VARCHAR(64)
- `created_at` DATETIME

### 5.3 `chat_session_prompt`

建议唯一键：`uk_session(session_id)`

字段：
- `id` BIGINT
- `session_id` BIGINT
- `tenant_id` VARCHAR(64)
- `content` TEXT
- `version` BIGINT
- `updated_at` DATETIME
- `updated_by` BIGINT
- `created_at` DATETIME
- `created_by` BIGINT
- `deleted` TINYINT(1)

## 六、API 契约草案（可直接联调）

统一返回沿用 `ApiResponse`。

### 6.1 获取系统级当前配置
- `GET /api/v1/chat/prompts/system/current?appCode=chat&modelRoute=default`

响应 data 示例：
```json
{
  "tenantId": "default",
  "appCode": "chat",
  "modelRoute": "default",
  "draftContent": "你是企业知识助手...",
  "draftVersion": 7,
  "publishedContent": "你是企业知识助手...",
  "publishedVersion": 6,
  "publishedAt": "2026-05-06 18:00:00"
}
```

### 6.2 保存系统级草稿
- `PUT /api/v1/chat/prompts/system/draft`

请求示例：
```json
{
  "tenantId": "default",
  "appCode": "chat",
  "modelRoute": "default",
  "draftContent": "你是企业知识助手，回答要先给结论...",
  "draftVersion": 7
}
```

冲突响应：`PROMPT_VERSION_CONFLICT`（409）

### 6.3 发布系统级提示词
- `POST /api/v1/chat/prompts/system/publish`

请求示例：
```json
{
  "tenantId": "default",
  "appCode": "chat",
  "modelRoute": "default",
  "draftVersion": 8,
  "publishNote": "优化工具调用约束"
}
```

### 6.4 更新会话级提示词
- `PUT /api/v1/chat/sessions/{sessionId}/prompt`

请求示例：
```json
{
  "content": "本会话请优先输出步骤清单，再给代码",
  "version": 3
}
```

响应 data 示例：
```json
{
  "sessionId": 10086,
  "content": "本会话请优先输出步骤清单，再给代码",
  "version": 4,
  "updatedAt": "2026-05-06 18:10:00"
}
```

## 七、编排层拼接规则（冻结）

按顺序拼接：
1. 系统级 `publishedContent`
2. 会话级 `content`（为空则跳过）
3. 运行时安全护栏（不可编辑）

并返回：
- `effectivePromptHash`：`SHA-256(systemPublishedVersion + sessionVersion + content)`

用于排障：同一请求在日志中可追踪是否命中同一提示词版本。
