# ARCH-REVIEW-20260428-003 chat 模块实施级目录与接口清单评审

### 一、可落地性结论
- 结论：可落地。
- 依据：
  - `gijela-core-llm` SDK 已稳定，可直接作为 `gijela-core-chat` 依赖。
  - 当前缺口主要是“实施级清单”而非技术可行性。

### 二、关键问题与调整建议
1. 问题：未形成“可直接建目录/建类”的实施清单。
   - 位置：ARCH-REVIEW-20260428-002 第三章（MVP 路径）
   - 风险：落地时仍需二次讨论，影响节奏。
   - 建议：冻结后端/前端目录、核心类名、最小 API 契约。
   - 优先级：P0

2. 问题：同步与流式协议字段未细化到 DTO 层。
   - 位置：ARCH-REVIEW-20260428-002 第二章问题3
   - 风险：联调阶段字段反复变更。
   - 建议：先冻结 DTO：
     - `ChatCompletionRequest`：`sessionId`、`messages`、`model?`、`temperature?`、`maxTokens?`、`skills?`
     - `ChatCompletionResponse`：`sessionId`、`content`、`finishReason`、`usage?`
   - 优先级：P0

3. 问题：技能路由与 MCP 模拟边界未落到接口层。
   - 位置：ARCH-REVIEW-20260428-002 第二章问题5
   - 风险：Skill/MCP 混写在 Controller。
   - 建议：
     - `SkillRegistry`（内置技能注册）
     - `McpGateway`（外部/Mock MCP 调用）
     - `ChatOrchestratorService`（统一编排入口）
   - 优先级：P0

4. 问题：会话状态与审计落点未固定。
   - 位置：ARCH-REVIEW-20260428-002 第二章问题4/6
   - 风险：会话与审计实现发散。
   - 建议：
     - `ConversationStore` 抽象（MVP 内存实现，预留 Redis 实现）
     - 审计字段固定：`tenantId`、`requestId`、`sessionId`、`action`、`result`
   - 优先级：P1

5. 问题：前端联调页最小能力未清单化。
   - 位置：ARCH-REVIEW-20260428-002 第三章
   - 风险：页面先做 UI 后补协议，返工大。
   - 建议：`gijela-bloom-chat` MVP 只做：
     - 会话列表（本地）
     - 消息窗口（同步/流式）
     - 技能开关区（skills/mcp mock）
   - 优先级：P0

### 三、最小落地路径（MVP）
- 第一步：后端目录与类骨架（不含复杂业务）
  - `gijela-core/gijela-core-chat/`
    - `controller/ChatController.java`
    - `service/ChatOrchestratorService.java`
    - `service/ConversationStore.java`
    - `service/impl/InMemoryConversationStore.java`
    - `adapter/llm/OpenAiChatAdapter.java`
    - `adapter/skill/SkillRegistry.java`
    - `adapter/mcp/McpGateway.java`
    - `domain/dto/ChatCompletionRequest.java`
    - `domain/dto/ChatCompletionResponse.java`
    - `domain/dto/StreamChatRequest.java`
    - `domain/vo/ChatEventVO.java`
    - `config/ChatModuleConfig.java`
- 第二步：前端目录与页面骨架
  - `gijela-bloom/gijela-bloom-chat/`
    - `src/api/chat.ts`
    - `src/store/chat.ts`
    - `src/views/ChatPage.vue`
    - `src/components/ChatWindow.vue`
    - `src/components/SkillPanel.vue`
    - `src/types/chat.ts`
- 第三步：联调与验收
  - 同步接口返回 `ApiResponse`
  - 流式接口 SSE 事件严格按 `start/delta/tool_call/tool_result/error/done`
  - 完成 4 条冒烟：同步、流式、工具调用、中断恢复

### 四、待拍板决策
1. `gijela-core-chat` 会话存储 MVP 选内存还是 Redis（建议：内存先跑通，P1 切 Redis）。
2. `gijela-bloom-chat` 是否复用 `pistil` 登录态（建议：复用）。
3. MCP mock 的数据源放本地静态文件还是内存映射（建议：本地静态 JSON）。
4. 流式前端是否优先 `EventSource` 还是 `fetch + ReadableStream`（建议：先 `fetch + ReadableStream`，兼容 header 带 token）。
