# ARCH-REVIEW-20260509-004 示例文档包与使用方式评审

### 一、可落地性结论
- 结论：可落地。
- 依据：模板已经齐备，但纯模板对首次使用者仍偏抽象。补一套示例文档可以显著降低理解成本，同时只放在 `00-governance/examples`，不会污染 `01-active` 与 `04-bugs` 的真实状态视图。

### 二、关键问题与调整建议
1. 问题：模板只有骨架，没有示例语境。
   - 位置：00-governance / 模板体系
   - 风险：使用者虽然知道该填什么栏目，但不清楚栏目粒度，容易写成“空标题 + 空要点”。
   - 建议：补一组同主题示例，覆盖 `REQ`、`ARCH-REVIEW`、`BUG` 三类常用文档。
   - 优先级：P0

2. 问题：若把示例放进 `01-active`，会干扰当前工作视图。
   - 位置：01-active / 目录边界
   - 风险：真实需求与示例文档混在一起，会降低索引可信度。
   - 建议：示例统一放在 `00-governance/examples`，通过 README 与 index 挂链接。
   - 优先级：P0

3. 问题：示例若脱离当前仓库语境，参考价值有限。
   - 位置：示例内容设计
   - 风险：示例看起来完整，但无法指导当前仓库的前后端分工与接口约束。
   - 建议：示例主题优先贴合现有“日志看板/导出/权限/审计”场景，保证可参考性。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：在 `00-governance/examples` 下补三类示例文档。
- 第二步：在治理 README、Active README 与索引页挂出入口。
- 第三步：后续新成员优先参考示例，再复制模板起稿。
