# ARCH-REVIEW-20260509-002 requirements 模板补齐与落地方式评审

### 一、可落地性结论
- 结论：可落地。
- 依据：上一轮评审已完成治理规则统一，本轮仅补齐模板层，未引入新的流程分叉；模板内容与仓库现有“最小必要改动、模块边界清晰、中文文档、联动更新”原则一致，可直接执行。

### 二、关键问题与调整建议
1. 问题：当前治理规则已定义，但缺少统一模板承载。
   - 位置：00-governance / README / “模板清单”缺失
   - 风险：后续新建需求、评审、缺陷、决策文档时，字段缺失或写法漂移，导致评审与开发沟通成本升高。
   - 建议：补齐 `REQ`、`ARCH-REVIEW`、`BUG`、`ADR` 四类模板，并在治理文档与索引页挂入口。
   - 优先级：P0

2. 问题：Active 与 Decision 区缺少模板引用路径。
   - 位置：01-active / README；03-decisions / README
   - 风险：使用者即使知道有模板，也不一定能快速找到，执行仍可能回到自由发挥模式。
   - 建议：在对应 README 直接挂模板链接，降低使用门槛。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：在 `00-governance` 下补齐四类模板文件。
- 第二步：在 `README` 与 `index.md` 中挂出模板入口。
- 第三步：后续所有新需求、新评审、新缺陷、新 ADR 一律优先从模板复制。
