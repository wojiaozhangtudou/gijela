# ARCH-REVIEW-20260509-001 requirements 文档体系与 .github 规范统一评审

### 一、可落地性结论
- 结论：有条件可落地。
- 依据：当前 `docs/requirements` 已完成分层归档，但与 `.github/copilot-instructions.md`、`.github/instructions/pistil-backend.instructions.md`、`.github/instructions/pistil-frontend.instructions.md` 的统一约束还未显式对齐，主要缺少“模块边界、文档职责、联动更新”三类规则声明。补齐后即可稳定执行。

### 二、关键问题与调整建议
1. 问题：治理文档未显式承接仓库级规则。
   - 位置：00-governance / README / “目标、约束”
   - 风险：需求文档结构虽然收敛，但执行时仍可能出现与仓库级规范脱节，导致前后端职责漂移或文档口径不一致。
   - 建议：在治理文档中增加“与 `.github` 规则统一”的明确条款，补充中文文档、模块边界、接口/权限/缓存变更需同步更新文档等要求。
   - 优先级：P0

2. 问题：Active 区仅定义目录结构，未定义主文档最小内容。
   - 位置：01-active / README / 全文
   - 风险：后续新需求可能继续出现“只有标题没有契约”的主文档，评审无法落地，开发容易越界实现。
   - 建议：补充主文档最小字段：背景、目标、范围、不做什么、影响模块、验收标准；跨模块需求需显式写职责分工。
   - 优先级：P0

3. 问题：索引页对“导航型索引”约束不够明确。
   - 位置：index.md / “当前状态、后续维护规则”
   - 风险：后续可能再次把历史记录、过程日志堆回索引页，重回不可维护状态。
   - 建议：在索引页增加“只保留导航、状态、最新评审入口”的规则，并把最新评审作为单独入口维护。
   - 优先级：P1

4. 问题：Backlog 与 ADR 的适用边界不够清楚。
   - 位置：02-backlog / README；03-decisions / README
   - 风险：轻量池、正式需求、长期决策三者混写，后续检索和归档成本会上升。
   - 建议：补充“何时进入 01-active”“什么级别才单独写 ADR”的判定规则，控制文档数量。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：补齐 `00-governance/README.md`，显式承接 `.github` 统一规范。
- 第二步：更新 `01-active/README.md`、`02-backlog/README.md`、`03-decisions/README.md`，明确边界与最小内容要求。
- 第三步：更新 `index.md`，只保留导航、状态与最新评审入口，避免重新膨胀。

### 四、待拍板决策

2. Bug 修复阶段是否单独新增 `04-bugs/` 目录，还是继续挂靠到对应 `01-active/REQ-*` 目录下。
3. 是否需要补一份统一模板文件（如 `REQ-TEMPLATE.md`、`ARCH-REVIEW-TEMPLATE.md`），进一步降低书写差异。
