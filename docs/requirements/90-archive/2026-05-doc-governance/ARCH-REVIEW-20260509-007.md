### 二、关键问题与调整建议
1. 问题：流式 usage 统计链路在兼容模型下存在完成时机偏差。
   - 位置：REQ-20260509-001 / 3.1 In Scope（流式解析修复）

   - 建议：完成事件仅在 `[DONE]` 触发，并保留“usage-after-stop”回归测试。
   - 优先级：P0

2. 问题：日志清理与概览查询存在缓存一致性缺口。
   - 位置：REQ-20260509-001 / 8. 前端交互；9. 性能与稳定性
   - 风险：用户已清空日志但仍看到旧指标，降低看板可信度。
   - 建议：清理接口后联动缓存失效；实时核心指标绕过缓存。
   - 优先级：P0

3. 问题：运行时日志粒度不足，难以定位输出异常。
   - 位置：REQ-20260509-001 / 6.3 事件日志
   - 风险：只有粗粒度事件时，无法还原模型流式输出与 token 增量关系。
   - 建议：保留 `chat.delta` 明细日志，同时在查询与页面层保持字段透传。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：修复流式完成时机，保障 token 可观测性基线。
- 第二步：打通清日志与缓存一致性，保证看板数据可信。
- 第三步：补齐 `chat.delta` 与页面展示，提升排障粒度。
