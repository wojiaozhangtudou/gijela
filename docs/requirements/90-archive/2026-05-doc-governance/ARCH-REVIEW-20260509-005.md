# ARCH-REVIEW-20260509-005 使用顺序与 Bug 总表规范评审

### 一、可落地性结论
- 结论：可落地。
- 依据：当前 requirements 体系已具备目录、模板、示例与缺陷分区，但“先做什么、后做什么”以及 `BUG-LIST.md` 每列怎么填还不够明确。补齐这两处后，执行成本会进一步下降，且不改变现有结构。

### 二、关键问题与调整建议
1. 问题：索引页缺少面向使用者的顺序指引。
   - 位置：index.md / 模板与示例之后
   - 风险：首次使用者即使看到完整目录，也不一定知道应从 Backlog、Active、Bug 还是 ADR 开始，容易走错入口。
   - 建议：新增“使用顺序”小节，按 Backlog → Active → Review → Bugs / ADR → Archive 给出操作路径。
   - 优先级：P0

2. 问题：Bug 总表只有表头，没有字段口径。
   - 位置：04-bugs / BUG-LIST.md / 全文
   - 风险：不同人对状态、优先级、来源需求的理解不一致，后续统计和跟踪会失真。
   - 建议：补充字段规范与维护规则，统一 `优先级`、`状态`、`来源需求` 的填写方式。
   - 优先级：P0

3. 问题：缺陷总表与明细文档的关系未写清。
   - 位置：04-bugs / BUG-LIST.md / 使用说明
   - 风险：可能只维护总表，不落明细，导致根因、修复、验证信息丢失。
   - 建议：明确“总表只管进行中状态，明细文档承载复现、根因、修复、验证”。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：在 `BUG-LIST.md` 补字段规范与维护规则。
- 第二步：在 `index.md` 新增“使用顺序”小节。
- 第三步：后续所有新增 Bug 按总表 + 明细双轨记录。

### 四、待拍板决策
1. `BUG-LIST.md` 的状态值是否要固定为枚举，不允许自由发挥。
2. 是否需要在总表中增加“目标修复版本”字段。
