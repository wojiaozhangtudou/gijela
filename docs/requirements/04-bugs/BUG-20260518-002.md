# BUG-20260518-002 保存后重开编辑页画布空白（数据已存在）

## 1. 问题现象
- 发生时间：2026-05-18
- 触发条件：流程保存后重新进入编辑页。
- 用户影响：后端详情接口返回 `nodes/edges` 正常，但画布看起来为空，误判为数据丢失。

## 2. 影响范围
- 模块：chat-flow 前端编辑器
- 环境：本地开发环境
- 严重级别：P1

## 3. 复现步骤
1. 新建流程并在画布添加节点、连线后保存。
2. 离开编辑页并重新打开同一流程。
3. 接口返回含 `nodes/edges`，但画布无可见节点。

## 4. 预期结果
- 重开编辑页后应自动聚焦到已保存节点，节点与连线可见。

## 5. 实际结果
- 画布未自动聚焦，视觉上呈现空白。
- 控制台出现 `TypeError: Cannot read properties of undefined (reading 'source')`，触发点在 VueFlow `Edge` 渲染链路。

## 6. 根因分析
- 加载完成后未执行视口回中，历史视口状态可能停留在偏移位置，导致节点位于可视区域之外。
- `load()` 中对持久化 `edges` 未做合法性清洗，存在异常/不完整边数据时会触发 VueFlow 渲染异常，进而导致整画布不可见。

## 7. 修复方案
- 在 `WorkflowEditor.load()` 中加载完 `nodes/edges` 后执行 `fitView({ padding: 0.2 })`。
- 无定义数据时主动清空 `nodes/edges`，避免残留状态。
- 为 `VueFlow` 显式设置 `width/height: 100%`，并在编辑区容器补齐 `min-height: 0`，防止回显时高度塌陷导致“空白画布”。
- 对 `nodes/edges` 执行严格归一化与过滤（缺失 `id/type/sourceNodeId/targetNodeId` 或引用不存在节点的边直接丢弃），避免 `Edge` 渲染阶段异常。
- 将节点渲染临时切换为 VueFlow 内置 `default` 节点（业务类型保留在 `data.type`），规避自定义节点插槽渲染不稳定导致的空白风险。
- 补充画布容器高度与尺寸诊断日志（`画布就绪/当前画布`），用于确认是否存在容器尺寸塌陷或视口异常。
- 为 `node-default` 提供显式节点模板并内置左右 `Handle`，确保已保存 `edges` 在回显时能正确计算连线锚点，避免再次触发边渲染异常。
- 增加“连线渲染开关”应急兜底：重开流程时优先保证节点可见，连线按需手动开启，用于隔离 `Edge` 渲染导致的整画布空白问题。
- 追加视口强制重置策略：加载后先 `setViewport({x:0,y:0,zoom:1})` 再 `fitView`，规避历史缩放/平移状态污染导致节点落在可视区外。
