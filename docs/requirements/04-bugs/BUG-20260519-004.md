# BUG-20260519-004：Controller 缺少完整异常捕获

## 问题分类
`稳定性缺陷` → 不完整的错误处理可能导致服务不稳定和信息泄露

## 问题描述

Completion 端点（POST /completions）的异常处理 **只捕获了业务异常**（NoSuchElementException、IllegalArgumentException、IllegalStateException），但 **缺少技术异常的捕获**。

### 当前实现
```java
@PostMapping("/completions")
public ApiResponse<ChatflowCompletionVO> completion(@RequestBody @Valid ChatflowCompletionDTO dto) {
    try {
        return ApiResponse.ok(conversationService.completion(dto));
    } catch (NoSuchElementException ex) {
        return ApiResponse.fail(ErrorCode.NOT_FOUND.getCode(), ex.getMessage(), null);
    } catch (IllegalArgumentException ex) {
        return ApiResponse.fail(ErrorCode.INVALID_ARGUMENT.getCode(), ex.getMessage(), null);
    } catch (IllegalStateException ex) {
        return ApiResponse.fail(ErrorCode.ILLEGAL_STATE.getCode(), ex.getMessage(), null);
    }
    // ❌ 缺少其他异常捕获！
}
```

**位置**：ChatflowConversationController.java 第 82-92 行

## 可能遗漏的异常情况

### 1. JSON 处理异常
```
JsonProcessingException
  ↓ 原因：工作流输入 JSON 序列化失败
  ↓ 来源：inputs 中包含无法序列化的对象
  ↓ 后果：返回 500 Internal Server Error，堆栈暴露
```

### 2. 超时异常
```
TimeoutException / WorkflowTimeoutException
  ↓ 原因：工作流执行超过 60s 阈值
  ↓ 来源：WorkflowRunService.startRun() 或 getRunDetail()
  ↓ 后果：返回 500 错误，而应返回业务友好的 408 timeout
```

### 3. 其他运行时异常
```
NullPointerException
  ↓ 原因：工作流返回的 finalResult 格式异常
  ↓ 来源：extractAnswer() 方法未做防御性检查
  ↓ 后果：返回 500 错误，缺少上下文信息

RuntimeException（来自工作流服务）
  ↓ 原因：工作流引擎的内部错误
  ↓ 来源：WorkflowService / WorkflowRunService
  ↓ 后果：返回 500 错误，堆栈跟踪暴露敏感信息
```

### 4. 数据库异常
```
DataAccessException
  ↓ 原因：消息存储、Session 更新失败
  ↓ 来源：messageMapper.insert() / sessionMapper.updateById()
  ↓ 后果：返回 500 错误，可能泄露 SQL 或数据库结构
```

## 影响范围

### 用户体验
- ❌ 返回 500 错误而不是业务错误（400/408）
- ❌ 错误信息非常技术性，用户无法理解

### 系统稳定性
- ⚠️ 日志中可能打印完整堆栈跟踪，导致日志文件快速增长
- ⚠️ 某些敏感异常（如 SQL 错误）会在错误响应中暴露

### 后端维护
- ❌ 异常处理不一致：其他接口有完整异常捕获，这个端点没有
- ❌ 新增异常时容易忘记在这里也要处理

## 建议修复方案

### 1. 立即修复 completion 端点

```java
@PostMapping("/completions")
public ApiResponse<ChatflowCompletionVO> completion(@RequestBody @Valid ChatflowCompletionDTO dto) {
    try {
        return ApiResponse.ok(conversationService.completion(dto));
    } catch (NoSuchElementException ex) {
        logger.warn("会话不存在: {}", dto.getSessionId());
        return ApiResponse.fail(ErrorCode.NOT_FOUND.getCode(), "会话不存在", null);
    } catch (IllegalArgumentException ex) {
        logger.warn("参数无效: {}", ex.getMessage());
        return ApiResponse.fail(ErrorCode.INVALID_ARGUMENT.getCode(), ex.getMessage(), null);
    } catch (IllegalStateException ex) {
        logger.warn("状态异常: {}", ex.getMessage());
        return ApiResponse.fail(ErrorCode.ILLEGAL_STATE.getCode(), ex.getMessage(), null);
    } catch (JsonProcessingException ex) {
        logger.error("工作流输入序列化失败", ex);
        return ApiResponse.fail(ErrorCode.INTERNAL_ERROR.getCode(), "数据处理失败", null);
    } catch (TimeoutException ex) {
        logger.warn("工作流执行超时");
        return ApiResponse.fail(ErrorCode.TIMEOUT.getCode(), "工作流执行超时（60秒）", null);
    } catch (Exception ex) {
        logger.error("工作流执行异常", ex);
        return ApiResponse.fail(ErrorCode.INTERNAL_ERROR.getCode(), "服务内部错误", null);
    }
}
```

### 2. 后续完整化：所有端点

建议为整个 Controller 添加一个统一的 @ExceptionHandler：

```java
@RestControllerAdvice
public class ChatflowExceptionHandler {
    
    @ExceptionHandler(JsonProcessingException.class)
    public ApiResponse<Void> handleJsonException(JsonProcessingException ex) {
        logger.error("JSON处理失败", ex);
        return ApiResponse.fail(ErrorCode.INTERNAL_ERROR.getCode(), "数据处理失败", null);
    }
    
    @ExceptionHandler(TimeoutException.class)
    public ApiResponse<Void> handleTimeout(TimeoutException ex) {
        logger.warn("操作超时");
        return ApiResponse.fail(ErrorCode.TIMEOUT.getCode(), "操作超时", null);
    }
    
    @ExceptionHandler(Exception.class)
    public ApiResponse<Void> handleGenericException(Exception ex) {
        logger.error("未预期的异常", ex);
        return ApiResponse.fail(ErrorCode.INTERNAL_ERROR.getCode(), "服务内部错误", null);
    }
}
```
