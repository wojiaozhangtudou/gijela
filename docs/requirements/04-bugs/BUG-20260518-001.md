# BUG-20260518-001 校验接口在无草稿版本时返回 500

## 1. 问题现象
- 发生时间：2026-05-18
- 触发条件：在流程编辑页点击“校验”，且流程尚未生成可用草稿版本（如 `current_draft_version=1` 且 `cf_workflow_version` 无对应 draft 记录）。
- 用户影响：前端提示“校验出错”，后端返回 HTTP 500，无法获得可读校验结果。

## 2. 影响范围
- 模块：chat-flow 前端编辑器 / chat-flow 后端校验服务
- 环境：本地开发环境（workflowId: `wf_5`）
- 严重级别：P1

## 3. 复现步骤
1. 创建新流程，不执行“保存”。
2. 进入编辑器后直接点击“校验”。
3. 观察请求 `/api/v1/chat-flow/workflows/{id}/validate` 返回 500。

## 4. 预期结果
- 校验接口应返回可解析的业务结果（如 `valid=false` + `issues`），而不是 500。

## 5. 实际结果
- 后端抛出未兜底异常导致 500。

## 6. 根因分析
- 后端 `validateWorkflow()` 直接依赖 `buildDraftDetail()`，当无草稿版本时触发 `IllegalStateException` / `NoSuchElementException`，控制器未捕获该类异常，最终透出 500。
- 前端“校验”未先持久化当前画布，导致更容易命中“无草稿可校验”的场景。

## 7. 修复方案
- 后端：`validateWorkflow()` 增加“无草稿版本”兜底，统一写入 `issues` 并返回 `valid=false`，避免 500。
- 前端：点击“校验”前先静默保存当前草稿，再调用校验接口；校验失败时展示 `issues` 明细。
