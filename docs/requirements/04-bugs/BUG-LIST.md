# Bug 跟踪总表

## 使用说明
- 只记录当前仍在跟踪的问题。
- 关闭的问题可从本表移除，并保留对应 `BUG-*.md` 文档后续归档。

## 字段规范
- 编号：对应 `BUG-YYYYMMDD-序号`。
- 标题：一句话描述问题，避免使用“优化一下”“有问题”这类模糊表述。
- 来源需求：填写关联的 `REQ` 编号；若无正式需求，标注“独立缺陷”。
- 影响模块：按实际填写，如“前端 / 后端 / 安全 / 缓存 / 数据”。
- 优先级：使用 `P0 / P1 / P2`。
- 状态：建议使用 `new / analyzing / fixing / verifying / closed`。
- 责任人：填写当前主跟进人。
- 备注：补充版本、回归范围、风险提示等短说明。

## 维护规则
- 每新增一个进行中问题，同时补一份 `BUG-*.md` 明细文档。
- 状态进入 `closed` 后，可从总表移除，并在归档批次中保留明细文档。
- 同一问题不重复建单；若问题升级为新需求，迁移到 `02-backlog` 或 `01-active`。
