# BUG-20260519-002：Completion 工作流输入字段名不一致

## 问题分类
`设计-实现偏差` → 严重的数据契约问题

## 问题描述

在代码审查中发现，**Completion API 传递给工作流的输入字段名** 与 **设计文档中声明的字段名** 不一致。

### 设计文档声称
```json
{
  "query": "用户消息内容",
  "chat_history": "对话历史JSON",
  "conversation_id": "会话ID"
}
```
**来源**：ARCH-REVIEW-20260519-004.md 附录 A.2

### 实际实现
```java
Map<String, Object> inputs = new LinkedHashMap<>();
inputs.put("question", content);                    // ❌ 应为 "query"
inputs.put("history", buildHistoryJson(...));      // ❌ 应为 "chat_history"
inputs.putAll(readMap(session.getWorkflowInputs())); // 用户输入
// ❌ 缺少 "conversation_id"
```
**位置**：ChatflowConversationServiceImpl.java 第 197-199 行

## 根本原因

1. 设计文档编写于详细实现前，基于理想化的字段命名
2. 实现时为了简化选择了不同的字段名
3. 未进行文档-代码对齐检查

## 影响范围

### 工作流设计者端
- ❌ 期望接收 `query` 字段，但收到 `question`
- ❌ 期望接收 `chat_history` 字段，但收到 `history`
- ❌ 期望接收 `conversation_id` 字段，但收到 null

### 后续 Phase 2
- ❌ 系统变量注入设计要求 `sys.query` 等前缀，但当前没有标准化

### 前端 + 中间件集成
- ❌ 日志系统无法通过 `conversation_id` 追踪对话链路

## 验证清单

- [x] 代码检查：确认字段名确实不同
- [ ] 工作流测试：创建测试工作流验证字段名
- [ ] 文档对齐：决定是改代码还是改文档

## 建议修复方案

### 方案推荐：修改代码以符合设计
**理由**：设计中的字段名更标准化，与 sys.* 前缀规划一致

```java
// 修复后的代码
Map<String, Object> inputs = new LinkedHashMap<>();
inputs.put("query", content);                    // 改 question → query
inputs.put("chat_history", buildHistoryJson(...)); // 改 history → chat_history
inputs.put("conversation_id", session.getSessionId()); // 新增
inputs.putAll(readMap(session.getWorkflowInputs())); // 用户输入可覆盖
```

### 修复位置
- 文件：`gijela-core-chat-flow/src/main/java/com/gijela/morpheus/chatflow/service/impl/ChatflowConversationServiceImpl.java`
- 行号：197-199（completion 方法）

### 修复后验证
1. 编译通过
2. 创建测试工作流验证输入数据结构
3. 前端 completion 调用不变（只改后端内部）

## 临时影响评估

- 工作流设计者现在不应该依赖 `query/chat_history/conversation_id`，改用实际字段 `question/history`
- 这是 Phase 1 发现的 Bug，修复不会影响已上线的其他功能
