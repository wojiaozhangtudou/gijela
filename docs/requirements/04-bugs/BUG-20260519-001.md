# BUG-20260519-001：Completion 请求契约设计缺陷 - workflowId 应从 Session 读取

## 问题分类
`架构缺口` → 需求文档（设计阶段）与实现代码之间的契约不一致 → **已通过 ARCH-REVIEW-20260519-004 澄清**

## 问题描述
Phase 1 实现完成后进行集成测试时发现，**`ChatflowCompletionDTO` 缺少 `workflowId` 字段**，导致以下不一致：

### 实现现状
- **DTO**：`ChatflowCompletionDTO` 仅包含 `sessionId`、`content`、`requestId`（三个字段）
- **VO**：`ChatflowCompletionVO` 包含 `sessionId`、`messageId`、`answer`、`workflowId`、`runId`、`createdAt`
- **Service**：`ChatflowConversationServiceImpl.completion()` 通过 `session.getWorkflowId()` 读取工作流 ID
- **控制器**：REST 端点 `POST /api/v1/chat-flow/chat/completions` 接收 `ChatflowCompletionDTO`

### 根本原因
设计文档（ARCH-REVIEW-20260519-003 第 9.1 节）定义的 API 请求体中**没有明确说明 `workflowId` 来源**。
实现时采取了合理的默认决策：**从 session 中读取工作流 ID**（因为一个会话绑定到一个工作流）。

但测试代码错误地假设需要在请求中传入 `workflowId`，导致类型校验失败。

## 影响范围
- **严重级别**：Major（不阻塞当前开发，但会影响前端调用、集成测试、API 文档的一致性）
- **涉及模块**：
  - 后端：`ChatflowConversationController.completion()`
  - 前端：`chatflow.ts` 的 `chatflowCompletion()` 函数
  - 文档：API 调用示例
- **实际影响**：
  - ✅ 后端代码实现逻辑正确（不需要改）
  - ⚠️ 前端 API 绑定需要确认：不应传入 `workflowId`
  - ⚠️ 集成测试假设错误，需调整
  - ⚠️ API 文档需澄清

## 建议修正方案

### 方案确认（已实施）
**采纳方案 A：保持现状**

- **理由**：工作流 ID 本质上是 Session 的属性，不应在每次消息时重复传入
- **后端**：✅ 已正确实现（无需改动）
- **前端**：✅ 已正确实现（API 调用不传 workflowId）
- **文档**：✅ 已完成澄清（ARCH-REVIEW-20260519-004）

### 设计澄清内容
- Completion API 请求体**不包含** `workflowId`（由 Session 自动关联）
- workflowId 仅在**创建 Session 时**指定
- 工作流切换时，通过**创建新 Session** 实现

参见：[ARCH-REVIEW-20260519-004.md](../01-active/ARCH-REVIEW-20260519-004.md)
