# BUG-20260519-003：缺少系统变量自动注入

## 问题分类
`架构缺口` → Phase 1 设计规划未完整实现

## 问题描述

设计规划中要求 Phase 1 需要自动注入三个系统变量，但代码实现中**完全缺少这些变量**。

### 设计规划的系统变量
根据 ARCH-REVIEW-20260519-003.md 第 10 节：
```
sys.query          → 最后一条用户消息内容
sys.chat_history   → 最近 10 轮对话历史（JSON 序列化）
sys.conversation_id → Session ID（用于链路追踪）
```

这些变量应该在调用工作流时**自动注入**，不需要用户在 Session 创建时手动配置。

### 实际实现
```java
// ChatflowConversationServiceImpl.java 第 197-199 行
Map<String, Object> inputs = new LinkedHashMap<>();
inputs.put("question", content);                    // 用户消息 ✅ 但字段名不对
inputs.put("history", buildHistoryJson(...));      // 对话历史 ✅ 但字段名不对
inputs.putAll(readMap(session.getWorkflowInputs())); // 用户输入 ✅
// ❌ 完全缺少 sys.conversation_id
```

## 根本原因

1. Phase 1 和 Phase 2 的功能分工不清晰
2. 设计文档中"系统变量"概念在代码需求清单中未体现
3. 与 BUG-20260519-002 的根源相同：字段名标准化缺失

## 影响范围

### 短期（当前）
- ❌ 工作流无法通过系统变量访问 conversation_id
- ❌ 日志、监控、链路追踪无法关联到对话
- ⚠️ 多工作流场景下，工作流无法自动知道对话 ID

### 中期（Phase 2 + 后续）
- ❌ 系统变量规范设计会与现有实现冲突
- ❌ 需要在 Phase 2 重新调整字段名
- ⚠️ 工作流定义会因版本差异导致兼容性问题

### 后期（运维）
- ❌ 链路追踪缺少对话关键信息
- ❌ 工作流错误诊断时无法快速定位对话上下文

## 建议修复方案

### 修复代码：立即添加系统变量注入

```java
// 修复后的 completion 方法
public ChatflowCompletionVO completion(ChatflowCompletionDTO dto) {
    ChatflowSessionEntity session = loadSession(dto.getSessionId());
    // ... 其他验证逻辑 ...

    String content = dto.getContent() == null ? null : dto.getContent().trim();
    
    // 构建工作流输入
    Map<String, Object> inputs = new LinkedHashMap<>();
    
    // 1. 自动注入系统变量（低优先级）
    inputs.put("sys.query", content);
    inputs.put("sys.chat_history", buildHistoryJson(session.getSessionId(), DEFAULT_HISTORY_LIMIT));
    inputs.put("sys.conversation_id", session.getSessionId());
    
    // 2. 合并用户自定义输入（高优先级，可覆盖系统变量）
    inputs.putAll(readMap(session.getWorkflowInputs()));
    
    // ... 后续工作流执行逻辑 ...
}
```

### 修复位置
- 文件：`gijela-core-chat-flow/src/main/java/com/gijela/morpheus/chatflow/service/impl/ChatflowConversationServiceImpl.java`
- 行号：197-199（completion 方法的输入构建部分）

### 修复策略
- **合并修复**：与 BUG-20260519-002 同一个代码改动解决
- **命名规范**：使用 `sys.*` 前缀标识系统变量
- **优先级**：系统变量 < 用户输入（用户输入可覆盖系统变量）

### 修复后验证
1. 编译通过
2. 集成测试：调用 completion API，检验工作流是否收到 `sys.conversation_id`
3. 工作流测试：创建测试工作流，访问系统变量
4. 无损更新：现有工作流不应该受影响（增加字段，不改现有字段）
