# ARCH-REVIEW-20260509-EXAMPLE 日志看板导出能力评审示例

### 一、可落地性结论
- 结论：有条件可落地。
- 依据：需求范围清晰，复用现有日志查询链路即可实现；但导出方式、权限粒度与大数据量场景需要先约束，否则会放大接口与性能风险。

### 二、关键问题与调整建议
1. 问题：导出协议未明确是同步下载还是异步任务。
   - 位置：6.1 请求
   - 风险：若默认同步导出，在大时间范围下容易超时，影响接口稳定性。
   - 建议：MVP 阶段限制导出条数或时间范围，先做同步导出；超过阈值时直接提示缩小范围。
   - 优先级：P0

2. 问题：权限点描述不够明确。
   - 位置：7. 权限与安全
   - 风险：若直接复用查看权限，可能让无导出需求的角色获得批量数据下载能力。
   - 建议：明确是否需要独立导出权限；若暂不拆权限，应在评审中明确这是阶段性选择。
   - 优先级：P1

3. 问题：导出内容缺少字段范围约束。
   - 位置：6.2 响应
   - 风险：字段一旦随查询结果直接透出，容易把调试字段或敏感字段一起导出。
   - 建议：在主需求文档补充导出字段白名单。
   - 优先级：P1

### 三、最小落地路径（MVP）
- 第一步：明确同步导出范围限制和字段白名单。
- 第二步：后端复用现有查询条件实现导出接口。
- 第三步：前端在工具栏接入导出按钮并补全状态提示。

### 四、待拍板决策
1. 是否单独新增“日志导出”权限点。
2. 导出上限按时间范围控制还是按记录数控制。
